## 앙상블 (Ensemble)

**여러 모델의 예측 결과를 합쳐서 최종 예측을 만드는 방법.**

핵심은 **서로 다른 실수를 하는 모델을 섞는 것**이다.

- LightGBM, XGBoost, CatBoost는 모두 트리 계열이라 틀리는 패턴이 비슷하다. 그래서 이들끼리 섞으면 효과가 작다.
- 선형 모델 + 트리 모델처럼 **성격이 다른 모델**을 섞으면 서로의 약점을 보완해서 효과가 크다.

> 참고: Random Forest(배깅)나 XGBoost(부스팅)도 내부적으로는 여러 트리를 합치는 앙상블이다.
> 이 문서의 방법들은 **이미 완성된 서로 다른 모델들을 바깥에서 합치는 방법**이다.

### 1. 평균 (Averaging)

회귀 문제에서 주로 사용한다.

| 모델 | 집값 예측 |
|---|---|
| 선형 회귀 | 5.0억 |
| LightGBM | 5.4억 |
| CatBoost | 5.3억 |
| **단순 평균** | **(5.0 + 5.4 + 5.3) / 3 = 5.23억** |

**가중 평균**: 성능이 좋은 모델에 더 큰 비중을 준다.

```
최종 = 0.2 × 5.0 + 0.4 × 5.4 + 0.4 × 5.3 = 5.28억
```

가중치는 검증(validation) 데이터에서 성능이 가장 좋은 조합으로 정한다.

### 2. 투표 (Voting)

분류 문제에서 주로 사용한다.

**Hard voting**: 각 모델이 낸 클래스로 다수결을 한다.

| 모델 | 예측 |
|---|---|
| 모델 A | 스팸 |
| 모델 B | 정상 |
| 모델 C | 스팸 |
| **결과** | **스팸 (2:1)** |

**Soft voting**: 각 모델이 낸 **확률을 평균**해서 결정한다. 보통 이쪽이 성능이 더 좋다.

| 모델 | 스팸일 확률 |
|---|---|
| 모델 A | 0.9 |
| 모델 B | 0.4 |
| 모델 C | 0.6 |
| **평균** | **0.63 → 스팸** |

Hard voting은 0.51과 0.99를 똑같이 한 표로 친다. Soft voting은 **모델이 얼마나 확신하는지**까지 반영한다.

### 3. 스태킹 (Stacking)

**여러 모델의 예측값을 입력으로 받아서 최종 답을 내는 모델을 하나 더 학습시키는 방법.**

"어떻게 합칠지"를 사람이 정하지 않고 모델이 학습한다. 자세한 내용은 아래에 정리했다.

## 스태킹 상세

### 비유

전문가 3명에게 집값을 물어보는 상황을 생각해 보자.

- **평균**: 세 명의 의견을 그냥 평균 낸다.
- **가중 평균**: "B가 제일 정확하니 B 의견을 40% 반영하자"처럼 사람이 비중을 정한다.
- **스태킹**: **팀장을 한 명 둔다.** 팀장은 과거 기록을 보면서 "A는 아파트는 잘 맞히는데 단독주택은 자주 틀린다", "B와 C 의견이 같으면 거의 맞는다" 같은 패턴을 **스스로 학습**한다. 그리고 세 명의 의견을 듣고 최종 판단을 내린다.

여기서 전문가 = **base model (1단계)**, 팀장 = **meta model (2단계)**.

### 구조

```
원본 feature (나이, 소득, 지역 ...)
        │
        ├──→ 선형 회귀  ──→ 예측 p1 ┐
        ├──→ LightGBM   ──→ 예측 p2 ├──→ [meta model] ──→ 최종 예측
        └──→ CatBoost   ──→ 예측 p3 ┘
```

meta model 입장에서는 **입력 feature가 `p1, p2, p3` 3개인 평범한 모델**이다.

| p1 (선형) | p2 (LGBM) | p3 (Cat) | 정답 y |
|---|---|---|---|
| 5.0 | 5.4 | 5.3 | 5.35 |
| 3.1 | 2.8 | 2.9 | 2.85 |
| ... | ... | ... | ... |

- meta model이 선형 회귀라면 `y = w1·p1 + w2·p2 + w3·p3 + b`를 학습한다. 가중 평균의 가중치를 **데이터에서 자동으로 찾는 것**과 비슷하다.
- meta model로 트리 모델을 쓰면 "p1과 p2의 차이가 클 때는 p2를 믿어라" 같은 조건부 판단도 학습할 수 있다.

### Out-of-Fold (OOF) 예측

#### 잘못된 방법

base model을 train 데이터 전체로 학습한 뒤, **같은 train 데이터를 예측**해서 `p1, p2, p3`를 만드는 방법이다.

- base model은 이미 본 데이터를 맞히기 때문에 예측이 정답과 거의 같다. 특히 트리 모델은 거의 외워버린다.
- 그러면 meta model은 "LightGBM은 항상 정확하다"고 잘못 학습한다.
- 결과적으로 새 데이터에서 성능이 떨어진다. **(과적합)**

#### 올바른 방법: K-Fold OOF 예측

train 데이터(예: 1000행)를 5개 fold(각 200행)로 나눈다.

```
train 데이터 1000행 (정답 y 있음)
┌──────┬──────┬──────┬──────┬──────┐
│fold1 │fold2 │fold3 │fold4 │fold5 │
└──────┴──────┴──────┴──────┴──────┘
  예측     ←────── 학습 ──────→        (1회차)
```

| 회차 | 학습 데이터 | 예측 대상 | 결과 |
|---|---|---|---|
| 1 | fold 2~5 (800행) | fold 1 (200행) | 1~200행의 p1 |
| 2 | fold 1,3,4,5 | fold 2 | 201~400행의 p1 |
| 3 | fold 1,2,4,5 | fold 3 | 401~600행의 p1 |
| 4 | fold 1,2,3,5 | fold 4 | 601~800행의 p1 |
| 5 | fold 1~4 | fold 5 | 801~1000행의 p1 |

- 5번을 돌면 **1000행 전체에 대한 p1 컬럼**이 완성된다.
- 각 행의 예측값은 **그 행을 학습에 쓰지 않은 모델**이 만든 값이다. 그래서 실제 새 데이터를 만났을 때의 예측과 성질이 비슷하다.
- 예측 대상 fold도 원래 train 데이터의 일부라서 **정답 y를 알고 있다**. 따라서 각 행마다 **(모델 예측값, 실제 정답)** 쌍이 생기고, 이게 meta model의 학습 데이터가 된다.
- 같은 과정을 LightGBM(→ p2), CatBoost(→ p3)에도 반복한다.

**왜 이렇게 하나?**
meta model이 배워야 하는 건 **"base model이 처음 보는 데이터에서 어떻게 틀리는지"**다. 이걸 배우려면 두 가지가 동시에 필요하다.

1. base model이 **안 본 데이터**에 대한 예측
2. 그 데이터의 **정답**

test 데이터는 최종 평가용이라 건드리면 안 된다. 그래서 **train 데이터 안에서 일부를 가려 놓고 "안 본 데이터" 역할을 시키는 것**이다.

### 전체 학습 흐름

1. **OOF 예측 생성**: 각 base model을 K-Fold로 학습하고, fold별 예측을 모아 `p1, p2, p3` 컬럼을 만든다.
   → 이 단계의 fold 모델들은 **meta model 학습 데이터를 만드는 용도**일 뿐이다.
2. **meta model 학습 (1번)**: `(p1, p2, p3) → y` 표 전체로 meta model을 한 번 학습한다.
3. **base model 재학습**: 각 base model을 **train 전체(1000행)로 다시 학습**한다. 800행보다 1000행으로 학습한 모델이 더 좋기 때문이다.
4. **실제 예측**:
   ```
   새 데이터 → base model 3개 (3단계) → p1, p2, p3 → meta model (2단계) → 최종 예측
   ```

| 대상 | 학습 횟수 | 용도 |
|---|---|---|
| base model (OOF용) | 3 × 5 = 15번 | meta model 학습 데이터 생성 |
| meta model | 1번 | 섞는 방법 학습 |
| base model (최종) | 3번 | 실제 예측용 |

> **변형**: 3단계에서 재학습하지 않고, 새 데이터에 대해 **fold 모델 5개의 예측을 평균**해서 쓰는 방식도 있다. Kaggle에서 자주 쓰며, 재학습 비용을 아끼고 예측이 안정되는 장점이 있다.
> scikit-learn의 `StackingClassifier`/`StackingRegressor`는 전체 데이터로 재학습하는 방식으로 동작한다.

### 데이터 역할 정리

| 데이터 | 정답 | 쓰임 |
|---|---|---|
| train (5개 fold) | 있음 | base model 학습 + OOF 예측 생성 → meta model 학습 |
| test | 평가 때만 사용 | 완성된 스태킹 전체의 최종 성능 확인 |

OOF 과정은 **전부 train 데이터 안에서만** 일어난다. test 데이터는 마지막까지 손대지 않는다.

### 실무 팁

- **meta model은 단순하게**: 보통 Linear/Logistic Regression이나 Ridge를 쓴다. 입력이 몇 개 안 되기 때문에 복잡한 모델을 쓰면 오히려 과적합된다.
- **base model은 다양하게**: 선형 + 트리 + (가능하면) KNN이나 신경망처럼 성격이 다를수록 효과가 크다.
- **비용**: 학습 시간이 `base model 수 × fold 수`만큼 늘고 구조도 복잡해진다. Kaggle처럼 0.1%가 중요한 곳에서는 많이 쓰지만, 실무에서는 단순 평균으로 충분한 경우도 많다.

- scikit-learn의 `VotingClassifier` / `VotingRegressor`: `voting="soft"`로 soft voting
- scikit-learn의 `StackingClassifier` / `StackingRegressor`: `cv=5`를 주면 OOF 예측 → meta model 학습 → base model 전체 재학습을 자동으로 처리
- 이 저장소의 [`house-prices-advanced-regression-techniques`](house-prices-advanced-regression-techniques/README.md)는 CatBoost + LightGBM + Lasso를 **가중 평균(블렌딩)**으로 합쳤다. 선형(Lasso) + 트리 모델을 섞은 사례다.

## 요약

| 방법 | 주 사용처 | 합치는 방식 |
|---|---|---|
| 평균 / 가중 평균 | 회귀 | 예측값을 (가중) 평균 |
| Hard voting | 분류 | 클래스 다수결 |
| Soft voting | 분류 | 확률 평균 |
| Stacking | 회귀·분류 | meta model이 합치는 방법을 학습 |

- 회귀는 **평균이나 가중 평균**, 분류는 **soft voting**이 기본이다.
- 성능을 최대로 끌어올리려면 **stacking**을 쓴다. 단, **out-of-fold 예측은 필수**다.
- 스태킹 한 줄 요약: **여러 모델의 예측을 어떻게 섞을지 자체를 또 다른 모델이 학습하는 앙상블.**

## 오차 상관과 오차 분석

모델을 개선할 때 전체 점수(RMSE, AUC 등) 하나만 보면 **얼마나** 틀리는지만 알 수 있다. 다음에 무엇을 고칠지 정하려면 **어디서, 어떻게, 어떤 모델들이 함께** 틀리는지를 봐야 한다. 이 장은 그 두 가지 도구를 프로젝트에 상관없이 쓸 수 있게 정리한 것이다.

| 도구 | 답하는 질문 | 주로 쓰는 때 |
|---|---|---|
| **오차 상관** | 모델들을 섞으면 이득이 있나? 어떤 모델을 추가해야 하나? | 앙상블·스태킹 구성 |
| **오차 분석** | 어디서 왜 틀리나? 모델을 고칠 문제인가, 데이터를 고칠 문제인가? | 다음 개선 방향 정하기 |

모든 분석은 **교차검증 예측(OOF, out-of-fold)** 위에서 한다. 학습에 쓴 데이터에 대한 예측은 외운 결과라서 오차가 실제보다 작게 보인다.

---

### 1. 오차 상관

#### 1-1. 예측 상관이 아니라 오차 상관을 본다

| 지표 | 계산 | 특징 |
|---|---|---|
| 예측 상관 | corr(예측 A, 예측 B) | 두 모델 모두 정답의 큰 흐름을 따라가므로 쓸 만한 모델끼리는 **늘 0.9 이상**. 차이가 잘 드러나지 않는다 |
| **오차 상관** | corr(예측 A − 정답, 예측 B − 정답) | 정답을 빼고 **틀린 부분끼리만** 비교한다. 두 모델이 같이 틀리는지가 분명히 보인다 |

예측 상관 0.99 는 "거의 같은 모델"처럼 보이지만, 오차 상관으로 보면 0.5일 수도 0.95일 수도 있다. 앙상블의 이득을 결정하는 것은 오차 상관이다.

#### 1-2. 섞으면 왜 좋아지나

두 모델의 오차가 서로 반대 방향이면 평균을 낼 때 상쇄된다.

```
오차 상관 낮음:  A +10%,  B −8%   → 평균 +1%     (크게 상쇄)
오차 상관 높음:  A +10%,  B +9%   → 평균 +9.5%   (거의 그대로)
```

오차의 표준편차가 a(더 좋은 모델), b(더 나쁜 모델)이고 오차 상관이 ρ 일 때, 가중 평균 w·A + (1−w)·B 의 오차 분산은

```
Var = w²a² + (1−w)²b² + 2w(1−w)·ρ·a·b
```

여기서 실무에 바로 쓸 수 있는 규칙이 나온다 (두 모델 모두 편향이 없다고 가정).

> **더 나쁜 모델 B 를 조금이라도 섞어서 이득이 나는 조건: ρ < a / b**

| 상황 | a / b | ρ | 섞으면 |
|---|---|---|---|
| 성능이 비슷한 두 모델 | ≈ 1.0 | 0.95 | 조금 좋아짐 (ρ < 1 이면 거의 항상) |
| 한쪽이 훨씬 약함 | 0.7 | 0.8 | **오히려 손해** → 섞지 않는 편이 낫다 |
| 한쪽이 약하지만 다르게 틀림 | 0.7 | 0.5 | 좋아짐 |

즉 **약한 모델은 충분히 다르게 틀려야만** 앙상블에 쓸모가 있고, 성능이 비슷하면 조금만 달라도 이득이 있다.

#### 1-3. 개별 성능과 다양성은 맞바꾸는 관계다

| 다양성을 얻는 방법 | 오차 상관 | 개별 성능 | 평가 |
|---|---|---|---|
| **보는 정보를 나눈다** (모델 A 는 피처 일부, B 는 나머지) | 낮아짐 | **둘 다 약해짐** | 대개 손해. 각 모델이 반쪽 정보로 예측한다 |
| **예측 방식을 다르게 한다** (트리 vs 선형 vs 신경망 vs kNN) | 중간 | 각자 강하게 유지 가능 | **가장 효과적**. 같은 정보를 보고도 다르게 틀린다 |
| 정답 변환·손실 함수를 다르게 한다 (log vs 원값, RMSE vs MAE) | 중간~높음 | 유지 | 보조 수단 |
| 같은 모델의 seed·샘플링만 바꾼다 | 매우 높음 (0.95~0.99) | 유지 | 흔들림을 줄이는 마무리 용도 |

**우선순위: 개별 성능 → 다양성.** 다양성을 위해 개별 모델을 크게 약하게 만드는 것은 대부분 손해다.

#### 1-4. 다양성을 주는 모델에 약점이 있을 때

예측 방식이 다른 모델은 다양성을 주지만, 고유한 약점도 함께 가져온다. 예를 들어 선형 모델과 신경망은 **학습 데이터 범위 밖의 입력에서 직선으로 연장되어 폭주**할 수 있다 (트리는 학습 범위 끝 값에 머문다).

이 경우 모델을 버리지 말고 **약점이 나타나는 영역에서만 빼는 장치**를 둔다.

```
입력이 학습 범위 안   → 모든 모델 블렌딩 (다양성 활용)
입력이 학습 범위 밖   → 안전한 모델만 사용 (폭주 차단)
```

주의: 학습 데이터 안에는 "범위 밖" 입력이 없으므로, **이 장치의 효과는 교차검증으로 측정할 수 없다.** 실제 평가(리더보드, 운영 데이터)로 확인해야 한다.

#### 1-5. 측정 방법

1. 모든 모델을 **같은 fold 분할**로 교차검증해 OOF 예측을 만든다.
2. 오차 = OOF 예측 − 정답 (평가 지표의 스케일에서. 예: RMSLE 면 log 스케일).
3. 모델 쌍마다 오차 상관을 계산하고, 단독 점수와 함께 표로 본다.
4. 후보 모델을 추가할지는 `ρ < a/b` 규칙과 실제 스태킹 교차검증 점수로 함께 판단한다.

### 2. 오차 분석

#### 2-1. 다섯 가지 관점

| 관점 | 질문 | 방법 |
|---|---|---|
| **집중도** | 오차가 고르게 퍼졌나, 몇 건에 몰렸나? | 제곱오차를 큰 순으로 정렬 → 상위 1%·5%·10% 의 비중. 상위 5% 를 뺀 나머지의 점수 |
| **그룹별 크기** | 어떤 종류의 데이터에서 많이 틀리나? | 카테고리 피처별, 수치 피처의 분위수 구간별로 건수·RMSE·**전체 오차 중 비중** |
| **편향 (방향)** | 한쪽으로 체계적으로 틀리나? | 그룹별 평균 오차 (예측 − 정답). + 면 과대, − 면 과소 예측 |
| **모델별 비교** | 그 그룹에서 어느 모델이 더 틀리나? | 같은 그룹 표에 모델별 RMSE 를 나란히 |
| **개별 사례** | 가장 크게 틀린 건은 어떤 데이터인가? | 오차 상위 20건의 원본 피처를 직접 읽는다 |

그룹 표에는 **건수와 오차 비중을 반드시 함께** 둔다. RMSE 가 큰 그룹이라도 10건뿐이면 전체 점수에 미치는 영향은 작고, 반대로 RMSE 가 보통이어도 건수가 많으면 비중이 크다.

#### 2-2. 오차 패턴별 처방

| 오차 패턴 | 의미 | 처방 |
|---|---|---|
| **한 모델만** 크게 틀림 | 그 모델의 문제 (정보 부족, 외삽, 설정) | 모델 교체, 그 모델에 정보 추가, 약점 영역 차단 |
| **모든 모델이 같이** 틀림 | 데이터의 문제 (피처에 정보 없음, 표본 부족, 정답 잡음) | 새 피처, 그룹별 별도 처리, 데이터 보강. **모델을 바꾸거나 섞어도 해결되지 않는다** |
| 특정 그룹에서 한 방향으로 틀림 (편향) | 그 그룹을 체계적으로 잘못 이해함 | 그 그룹을 구분하는 피처 추가, 그룹별 보정 |
| 오차가 극소수에 몰림 | 대부분은 이미 잘 맞힘 | 그 소수의 공통점을 찾아 공략. 공통점이 없으면 잡음으로 보고 한계로 인정 |
| 교차검증은 좋은데 실제 평가가 나쁨 | 학습 데이터에 없는 상황이 평가 데이터에 있음 (분포 차이, 범위 밖 입력) | 평가 데이터의 피처가 학습 범위를 벗어나는지 점검, 학습·평가 분포 비교. 오차 분석만으로는 보이지 않는다 |

**두 분석은 연결된다.** "모든 모델이 같이 틀리는 영역"은 곧 오차 상관이 높은 영역이다. 앙상블로는 줄일 수 없으므로, 오차 분석으로 그 영역을 찾아 데이터 쪽에서 고친다.

#### 2-3. 해석할 때 주의할 점

- **정답 값으로 나눈 그룹의 편향은 당연히 생긴다.** 정답 하위 10% 그룹은 거의 항상 과대 예측, 상위 10% 는 과소 예측으로 나온다 (예측이 평균 쪽으로 끌려가는 현상). 정답 구간별 편향은 "있는지"보다 **모델·버전 간 크기 비교**로 보고, 원인 해석은 피처로 나눈 그룹에서 한다.
- **작은 그룹의 숫자는 흔들린다.** 10건짜리 그룹의 RMSE 는 몇 건에 좌우된다. 건수를 함께 보고, 여러 fold·반복에서 일관되게 나오는지 확인한다.
- **그룹을 많이 나눠 보면 우연히 나쁜 그룹이 나온다.** 처방하기 전에 "그 그룹이 왜 어려운지" 피처로 설명이 되는지 확인한다.
- **교차검증 위의 분석은 학습 데이터 안의 문제만 보여 준다.** 평가 데이터에만 있는 문제(외삽, 분포 차이)는 평가 데이터의 피처를 직접 점검해야 찾을 수 있다.

### 3. 개선 사이클

```
 ┌─→ ① OOF 예측 만들기 (모든 모델, 같은 분할)
 │       │
 │   ② 오차 분석: 어디서, 누가 틀리나?
 │       ├ 한 모델만 틀림      → 그 모델 수정 (교체·정보 추가·약점 차단)
 │       ├ 모두 같이 틀림      → 데이터 수정 (피처·그룹 처리)
 │       └ 극소수·잡음         → 한계로 인정, 다른 영역으로
 │       │
 │   ③ 오차 상관: 섞을 여지가 있나?
 │       ├ 오차 상관 높음 (같이 틀림) → 예측 방식이 다른 강한 모델 추가
 │       └ 약한 모델은 ρ < a/b 일 때만 추가
 │       │
 │   ④ 평가 데이터 점검: 학습 범위 밖 입력, 분포 차이 → 보호 장치
 │       │
 │   ⑤ 교차검증 → 실제 평가 (교차검증으로 판단할 수 없는 선택은 실제 평가로 결정)
 └───────┘
```

지금까지의 프로젝트에서 개선 폭이 큰 순서는 대체로 **정보(피처·데이터 정렬) > 모델 종류와 앙상블 구성 > 하이퍼파라미터·seed** 였다.

## 통계 용어

위의 오차 상관·오차 분석에서 쓰는 통계 용어를 정리한다. 아래로 갈수록 앞의 개념을 이어서 쓴다.

```
편차 → 분산 → 표준편차
  └→ 공분산 → 피어슨 상관 → (순위로 바꾸면) 스피어만 상관
```

> 참고한 Claude 대화: https://claude.ai/code/session_01U7c2tcdyqmFgishS8Zh2LB

### 1. 편차·분산·표준편차

예시 데이터 (8개): `2, 4, 4, 4, 5, 5, 7, 9` → 평균 x̄ = 40 / 8 = **5**

#### 편차 (Deviation)

**각 값이 평균에서 얼마나 떨어져 있는지.**

```
편차 = xᵢ − x̄
```

| x | 2 | 4 | 4 | 4 | 5 | 5 | 7 | 9 |
|---|---|---|---|---|---|---|---|---|
| 편차 | −3 | −1 | −1 | −1 | 0 | 0 | +2 | +4 |
| 편차² | 9 | 1 | 1 | 1 | 0 | 0 | 4 | 16 |

- 편차의 합은 **항상 0**이다 (+와 −가 상쇄). 그래서 편차를 그냥 평균 내면 퍼진 정도를 알 수 없다 → 제곱해서 쓴다.

#### 분산 (Variance)

**편차 제곱의 평균. 데이터가 평균 주위에 얼마나 퍼져 있는지.**

```
분산 = Σ(xᵢ − x̄)² / n  = 32 / 8 = 4
```

- 제곱했기 때문에 **단위도 제곱**이 된다 (원 단위 → 원², m → m²). 원래 값과 직접 비교하기 어렵다.
- 제곱 때문에 **평균에서 멀리 떨어진 값의 영향이 크게 커진다.** 편차 4는 16, 편차 1은 1이라 16배 차이가 난다. 이것이 뒤에 나오는 "피어슨 상관이 이상치에 약한 이유"의 출발점이다.
- **n vs n−1**: 모집단 전체면 n으로 나누고, 표본으로 모집단을 추정할 때는 n−1로 나눈다 (표본 분산). 표본 평균이 표본 쪽으로 붙어 있어 분산이 작게 나오는 것을 보정하는 것이다. 데이터가 수만 행 이상이면 차이는 무시할 만하다. (`numpy.var`는 기본 n, `pandas.Series.var`는 기본 n−1)

#### 표준편차 (Standard Deviation)

**분산의 제곱근. 원래 단위로 되돌린 퍼짐 정도.**

```
표준편차 = √분산 = √4 = 2
```

- 단위가 원래 값과 같아서 해석이 쉽다: "평균 5에서 보통 2 정도 떨어져 있다".
- **RMSE는 오차(예측 − 정답)의 제곱 평균의 제곱근**이다. 오차의 평균이 0이면 RMSE = 오차의 표준편차가 된다. 위 1-2절 공식의 a, b가 바로 이 오차 표준편차다.

### 2. 공분산과 피어슨 상관 (Pearson)

#### 공분산 (Covariance)

**두 변수가 평균 대비 같은 방향으로 움직이는지.** 분산을 두 변수로 확장한 것이다.

```
공분산 = Σ(aᵢ − ā)(bᵢ − b̄) / n
```

| 행 i에서 | 편차 곱 | 의미 |
|---|---|---|
| a, b 둘 다 평균보다 큼 (또는 둘 다 작음) | **+** | 같이 움직임 |
| 한쪽만 평균보다 큼 | **−** | 반대로 움직임 |

- 단점: 값의 단위·크기에 따라 숫자가 달라져서 "얼마나 강한 관계인지" 비교할 수 없다.

#### 피어슨 상관계수

**공분산을 두 표준편차로 나눠 −1 ~ +1로 맞춘 것.**

$$r = \frac{\sum (a_i - \bar a)(b_i - \bar b)}{\sqrt{\sum (a_i - \bar a)^2}\sqrt{\sum (b_i - \bar b)^2}}$$

| r | 의미 |
|---|---|
| +1 | 완전히 같은 방향으로 직선 관계 |
| 0 | 직선 관계 없음 |
| −1 | 완전히 반대 방향으로 직선 관계 |

- **오차 상관**에서는 `aᵢ` = 모델 A의 i번째 행 오차, `bᵢ` = 모델 B의 i번째 행 오차다. 같은 행에서 두 모델이 같이 틀리는지를 본다.
- **오차의 크기 자체가 아니라 "같이 움직이는지"를 본다.** 두 모델 모두 오차가 작아도 상관은 높을 수 있고, 오차가 커도 상관은 낮을 수 있다.

#### 왜 이상치에 휘둘리나

각 행의 기여도가 **(A 편차) × (B 편차)** 라서, 편차가 큰 행은 사실상 제곱으로 기여한다.

| 행 | A 오차 | B 오차 |
|---|---|---|
| 1 | 0.01 | 0.03 |
| 2 | 0.03 | 0.01 |
| 3 | 0.02 | 0.04 |
| 4 | 0.04 | 0.02 |
| 5 | **0.90** | **0.90** |

- 행 1~4만 보면 두 모델은 서로 엇갈리게 틀린다 → **r = −0.6**
- 행 5 하나를 추가하면 → **r ≈ 0.999**
  - 행 5의 편차 곱(0.7 × 0.7 = 0.49)이 분자 전체(0.612)의 **80%**를 차지한다.
  - 평균이 0.2로 끌려 올라가면서 행 1~4가 전부 "평균보다 작은 쪽"으로 묶여, 원래 엇갈리던 행들까지 양의 곱을 만든다.
- 즉 피어슨 상관은 **큰 값 몇 개가 결과를 독차지**할 수 있다.

### 3. 스피어만 순위 상관 (Spearman)

**값을 순위로 바꾼 뒤 피어슨 상관을 구한 것.** "얼마나 틀렸나"가 아니라 **"두 모델이 틀린 순서가 같은가"**를 본다.

#### 계산 예시 (정상 행 5개, 오차 = −p)

| 행 | A 오차 | B 오차 | A 순위 | B 순위 | d | d² |
|---|---|---|---|---|---|---|
| 1 | −0.01 | −0.02 | 5 | 5 | 0 | 0 |
| 2 | −0.30 | −0.10 | 2 | 3 | −1 | 1 |
| 3 | −0.05 | −0.15 | 3 | 2 | 1 | 1 |
| 4 | −0.80 | −0.60 | 1 | 1 | 0 | 0 |
| 5 | −0.02 | −0.03 | 4 | 4 | 0 | 0 |

(가장 작은 값, 즉 가장 심하게 오탐한 행이 1위)

동점이 없으면 간단한 공식으로 계산할 수 있다.

$$\rho = 1 - \frac{6\sum d^2}{n(n^2-1)} = 1 - \frac{6 \times 2}{5 \times 24} = 0.9$$

- 가장 심한 행(4)과 가장 덜한 행(1)은 두 모델이 같게 봤고, 2·3위만 뒤바뀌어 0.9가 나왔다.
- 행 4의 값은 −0.80과 −0.60으로 다르지만 **순위는 둘 다 1위라 차이가 없다.**
- 실제 데이터는 동점이 많아서 위 공식 대신 **순위로 바꾼 뒤 피어슨을 구한다** (`scipy.stats.spearmanr`가 이렇게 계산한다).

```python
from scipy.stats import spearmanr, pearsonr, rankdata
a = [-0.01, -0.30, -0.05, -0.80, -0.02]
b = [-0.02, -0.10, -0.15, -0.60, -0.03]
spearmanr(a, b)[0]                      # 0.9
pearsonr(rankdata(a), rankdata(b))[0]   # 0.9 (같은 값)
```

#### 피어슨과 비교

| | 피어슨 | 스피어만 |
|---|---|---|
| 보는 것 | 값의 직선 관계 (크기 포함) | 순위의 일치 (순서만) |
| 이상치 | 크게 휘둘림 | 강함 (0.9든 900이든 1등일 뿐) |
| 비선형 단조 관계 | 낮게 나옴 | 잡아냄 |
| 확률 스케일(calibration) 차이 | 영향 받음 | 영향 없음 (순서만 같으면 1) |

- 앞의 이상치 예시(행 1~5)에 스피어만을 적용하면 **ρ = 0.2**로, 행 1~4의 엇갈림이 그대로 드러난다.
- **피어슨은 높은데 스피어만이 낮다** → 극단값 몇 개가 상관을 끌어올리고 있다는 신호.
- 사기 탐지처럼 점수 순으로 위에서부터 검토하거나 threshold로 자르는 문제에서는, 스피어만이 "두 모델이 사실상 같은 판단을 하는가"에 더 가깝다.

### 4. 잔차와 logloss

#### 잔차 (Residual)

```
잔차 = 실제값 − 예측값
```

> 이 문서의 "오차"는 `예측 − 정답`, 잔차는 `정답 − 예측`으로 **부호만 반대**다. 상관은 부호를 둘 다 뒤집어도 같으므로 오차 상관 = 잔차 상관이다.

**이진 분류에서**: 모델이 내는 `p`는 **"양성(사기)일 확률"**이고, 정답은 사기 `y = 1`, 정상 `y = 0`이다.

| 행 | y | p (사기 확률) | 잔차 y − p | 의미 |
|---|---|---|---|---|
| 사기 | 1 | 0.9 | +0.1 | 잘 맞춤 |
| 사기 | 1 | 0.2 | +0.8 | 놓침 |
| 정상 | 0 | 0.05 | −0.05 | 잘 맞춤 |
| 정상 | 0 | 0.7 | −0.7 | 오탐 |

- 사기 행 잔차 = `1 − p` (항상 **양수**: 덜 의심함)
- 정상 행 잔차 = `0 − p = −p` (항상 **음수**: 괜히 의심함)
- 0에 가까울수록 잘 맞춘 것이다.

#### logloss (로그 손실)

```
logloss = −[ y·log(p) + (1 − y)·log(1 − p) ]
```

- 행마다 계산되는 분류 오차. **확신하고 틀릴수록 벌점이 폭발적으로 커진다.**

| y | p | 잔차 | logloss |
|---|---|---|---|
| 1 | 0.5 | 0.5 | 0.69 |
| 1 | 0.1 | 0.9 | 2.30 |
| 1 | 0.01 | 0.99 | **4.61** |

- 잔차는 0.9 → 0.99로 조금 늘지만 logloss는 2배가 된다. 그래서 **logloss 상관은 "확신하고 틀리는 위험한 오답을 두 모델이 공유하는가"**를 강하게 반영한다.
- `log(0)`을 피하려고 p를 `[1e-15, 1 − 1e-15]`로 잘라서 계산한다.

### 5. 상관 지표 해석 시 주의점

#### 집단 차이가 만드는 착시

클래스처럼 **값의 수준이 확연히 다른 집단이 섞여 있으면**, 집단 간 차이만으로 상관이 높게 나온다.

사기 탐지 예시 (두 모델 비교, 사기 비율 1.7%):

| 구간 | 행 수 | 잔차 상관 (pearson) | 잔차 순위 상관 (spearman) | logloss 상관 |
|---|---|---|---|---|
| 전체 | 699,960 | 0.979 | 0.926 | 0.982 |
| 사기 행 | 11,689 | 0.956 | 0.967 | 0.967 |
| 정상 행 | 688,271 | 0.913 | 0.923 | 0.891 |

- 전체 값(0.979)이 **두 구간 값보다 모두 높다.** 사기 행은 잔차가 크고(`1 − p`) 정상 행은 0 근처(`−p`)라, 두 모델 모두 "사기 행은 크게, 정상 행은 작게"라는 같은 패턴을 보이기 때문이다. 사기 행 전체가 2절의 "행 5" 같은 이상치 역할을 한다.
- 그래서 **구간(클래스)별로 나눠 본 값이 진짜 정보**다.
- 사기 행 0.96대 → 두 모델이 **같은 사기 건을 같이 놓친다.** 앙상블로 recall을 올리기 어렵다.
- 정상 행이 상대적으로 낮음 (logloss 0.891) → **오탐하는 정상 거래가 모델마다 조금 다르다.** 평균을 내면 한 모델만 튄 오탐이 희석되어 precision이 조금 오를 여지가 있다.
- 정상 행 잔차는 전부 음수라서 "다른 방향으로 틀린다"가 아니라 **"다른 행을 틀린다"**로 읽어야 한다.

#### 상관 수준 대략 기준 (경험적)

| 오차 상관 | 의미 |
|---|---|
| ~0.95 이상 | 사실상 같은 모델. 앙상블 이득 거의 없음 |
| 0.7 ~ 0.9 | 보통. 약간의 이득 |
| 0.7 미만 | 다양성 높음. 단, 개별 성능이 충분할 때만 의미 있음 (`ρ < a/b` 규칙) |

#### 상관만으로 결론 내리지 않는다

상관은 "섞을 여지"를 보여 줄 뿐이다. 실제로는 OOF 예측으로 다음을 함께 확인한다.

- 개별 모델 vs 블렌딩의 점수 (불균형 분류면 PR-AUC, 고정 FPR에서의 recall)
- 운영 threshold에서 두 모델이 놓친 양성(FN) 집합의 겹침 (Jaccard)
- 점수 상위 K개 안의 오탐(FP) 겹침

### 6. 용어 요약표

| 용어 | 식 | 한 줄 의미 |
|---|---|---|
| 편차 | xᵢ − x̄ | 평균에서 떨어진 거리. 합은 항상 0 |
| 분산 | Σ(xᵢ − x̄)² / n | 편차 제곱의 평균. 단위가 제곱, 큰 편차를 강조 |
| 표준편차 | √분산 | 원래 단위의 퍼짐 정도 |
| RMSE | √(Σ오차² / n) | 오차 평균이 0이면 오차의 표준편차 |
| 공분산 | Σ(aᵢ − ā)(bᵢ − b̄) / n | 두 변수가 같은 방향으로 움직이는지 (크기에 의존) |
| 피어슨 상관 | 공분산 / (σₐ·σᵦ) | −1~1로 맞춘 직선 관계. 이상치에 약함 |
| 스피어만 상관 | 순위에 대한 피어슨 | 순서의 일치. 이상치·스케일 차이에 강함 |
| 잔차 | y − ŷ | 정답 − 예측. 분류에서 사기 1−p, 정상 −p |
| logloss | −[y·log p + (1−y)·log(1−p)] | 확신하고 틀릴수록 큰 벌점 |
| 오즈 (odds) | p / (1 − p) | 일어날 확률 대 안 일어날 확률의 비 |
| log-odds | log(p / (1 − p)) | 분류 모델 내부 출력 단위. +0.7 ≈ 오즈 2배 |
| SHAP 값 | 예측 = 기준값 + Σ SHAP | 행 하나에서 피처 값이 예측을 평균 대비 얼마나 움직였나. 분류에서는 log-odds 눈금 위의 변동량 |

## SHAP (행별 피처 기여도)

**SHAP (SHapley Additive exPlanations): 예측값 하나를 "기준값 + 피처별 기여도의 합"으로 쪼개서, 행마다 각 피처 값이 예측을 얼마나 올리고 내렸는지 보여 주는 방법.**

> 참고한 Claude 대화: https://claude.ai/code/session_01U7c2tcdyqmFgishS8Zh2LB

---

### 1. 핵심: 예측 = 기준값 + 피처별 기여의 합

```
기준값 (평균 예측)       5.0억
+ 면적 (넓음)           +0.8억
+ 지역 (강남)           +0.6억
+ 연식 (오래됨)          −0.2억
──────────────────────────
= 이 집의 예측값         6.2억
```

- **기준값 (base value)**: 아무 정보도 없을 때의 예측. 보통 데이터 전체에 대한 모델 출력의 평균.
- **SHAP 값**: 그 행의 피처 값 때문에 예측이 **기준값에서 얼마나 움직였는지.**
- **합이 항상 정확히 맞는다 (additivity)**: 기준값 + 모든 SHAP 값 = 그 행의 예측값.

읽는 법: SHAP +0.8억은 "면적이 집값 중 0.8억을 차지한다"가 **아니다.** "이 집의 면적 값(넓음) 때문에 **평균적인 집보다** 0.8억 높게 예측됐다"는 뜻이다.

같은 피처라도 **행마다 SHAP 값이 다르다.**

| 집 | 면적 | 면적의 SHAP |
|---|---|---|
| 넓은 집 | 큼 | +0.8 |
| 보통 집 | 평균 정도 | ≈ 0 |
| 좁은 집 | 작음 | −0.5 |

---

### 2. 기여도를 나누는 방법: 섀플리 값 (Shapley value)

게임 이론에서 온 개념으로, **팀 성과를 각자에게 공정하게 나누는 방법**이다.

> 피처를 넣는 **순서를 바꿔 가며** 모델에 하나씩 넣고, 각 피처가 들어올 때 예측이 얼마나 변했는지를 **모든 순서에 대해 평균**한다.

피처 2개 예시:

| 모델이 아는 피처 | 예측 |
|---|---|
| 없음 | 5.0 |
| 면적만 | 5.6 |
| 지역만 | 5.4 |
| 면적 + 지역 | 6.2 |

| 피처 | 먼저 들어올 때 | 나중에 들어올 때 | 평균 (SHAP) |
|---|---|---|---|
| 면적 | 5.0 → 5.6 = +0.6 | 5.4 → 6.2 = +0.8 | **+0.7** |
| 지역 | 5.0 → 5.4 = +0.4 | 5.6 → 6.2 = +0.6 | **+0.5** |

검산: 0.7 + 0.5 = 1.2 = 6.2 − 5.0

- 순서에 따라 기여가 다른 이유는 **피처 간 상호작용** 때문이다 (넓은 집이 강남에 있으면 더 비싸짐). 그래서 모든 순서를 평균해 공정하게 나눈다.
- 피처가 n개면 순서가 n!개라 그대로는 계산할 수 없다. 그래서 모델 종류별로 빠른 계산법(Explainer)을 쓴다 → 6절.

| | 트리의 `feature_importance` (gain / split) | SHAP |
|---|---|---|
| 단위 | 모델 전체 | **행 하나하나** |

| 일관성 | 설정에 따라 순위가 뒤바뀔 수 있음 | 이론적으로 일관됨 |
| 전체 중요도 | 그대로 | 행별 \|SHAP\|의 평균 |

### 4. 분류 모델: 단위는 log-odds

분류 모델의 SHAP은 보통 **확률이 아니라 log-odds 단위**다. 덧셈이 맞아떨어지는 것도 log-odds 기준이다.

```
오즈      = p / (1 − p)
log-odds = log(p / (1 − p))

기준값 −4.0 (p ≈ 1.8%) + SHAP 합 +3.5 = −0.5 (p ≈ 38%)
```

#### SHAP 값은 log-odds 스케일에서의 눈금 단위 변동량이다

SHAP 값 자체는 평범한 실수다. 각 SHAP 값이 log-odds 함수에 무언가를 넣어 나온 결과가 아니라, **log-odds 눈금 위에서 예측을 몇 칸 움직였는지(변동량)**를 나타낸다.

```
기준값            −4.0   ← log-odds 값 (위치, 확률 1.8%)
+ CVV 재입력      +1.7   ← log-odds 눈금에서 1.7칸 위로 이동
+ 가맹점 위험     +1.2   ← 1.2칸 위로 이동
+ 인증 방식       −0.4   ← 0.4칸 아래로 이동
────────────────────
= 예측 점수        −1.5   ← 다시 log-odds 값 (위치, 확률 18%)
```

| 구분 | 의미 | 확률로 바꿀 수 있나 |
|---|---|---|
| 기준값, 예측 점수 | log-odds 눈금 위의 **위치** | 가능 (`p = 1 / (1 + e^(−점수))`) |
| SHAP 값 | 두 위치 사이의 **이동량** | **불가능.** SHAP 하나만 떼어 시그모이드에 넣으면 의미가 없다 |

온도로 비유하면 기준값·예측 점수는 "지금 기온 20℃" 같은 위치이고, SHAP 값은 "3℃ 올랐다" 같은 변화량이다. 같은 눈금을 쓰지만 의미가 다르다.

- SHAP +0.7 → 오즈가 e^0.7 ≈ **2배.** "확률 2배"가 아니라 **"오즈 2배"**다.
- 확률이 작을 때는 오즈 ≈ 확률이라 확률도 거의 2배지만, 확률이 커지면 달라진다.

| 원래 확률 | 오즈 | 오즈 × 2 | 바뀐 확률 |
|---|---|---|---|
| 1.7% | 0.017 | 0.035 | 3.4% (거의 2배) |
| 22% | 0.28 | 0.56 | **36%** (44%가 아님) |

- 확률로 바꾸면 덧셈이 성립하지 않으므로 "이 피처가 확률을 +10%p 올렸다"는 표현은 부정확하다. **방향과 상대 크기** 위주로 해석한다.

### 5. 주로 보는 그림

| 그림 | 보는 것 | 용도 |
|---|---|---|
| **waterfall / force** | 행 하나의 예측 분해 (1절 예시) | "이 거래는 왜 사기로 판정됐나?" |
| **beeswarm (summary)** | 모든 행의 SHAP을 피처별 점으로, 색 = 피처 값 | 중요도와 방향 (빨간 점이 오른쪽 → 값이 클수록 예측을 올림) |
| **bar** | 피처별 \|SHAP\| 평균 | 전체 중요도 순위 |
| **dependence (scatter)** | x = 피처 값, y = SHAP | 비선형 관계·임계점 (예: 금액이 어느 선을 넘으면 급증) |

```python
import shap
explainer = shap.Explainer(model, X_background)   # 모델 종류에 맞는 Explainer 자동 선택
sv = explainer(X_valid)

shap.plots.beeswarm(sv)
shap.plots.bar(sv)
shap.plots.waterfall(sv[0])
shap.plots.scatter(sv[:, "amount"], color=sv)
```

### 6. GBDT 말고 다른 모델에도 쓸 수 있나

**쓸 수 있다.** 섀플리 값은 "피처를 넣고 뺐을 때 예측이 어떻게 변하나"만 있으면 정의되므로 **모델 종류와 무관 (model-agnostic)**하다. 다만 계산 방법(Explainer)과 속도가 모델마다 다르다.

| 모델 | Explainer | 특징 |
|---|---|---|
| 트리 계열 (LightGBM, XGBoost, CatBoost, RandomForest) | `TreeExplainer` | 트리 구조를 이용해 **정확한 값을 빠르게** 계산. 수십만 행도 가능 |
| 선형 (Linear / Logistic Regression, Lasso, Ridge) | `LinearExplainer` | 식으로 바로 나온다 (아래). 매우 빠름 |
| 신경망 (PyTorch, TensorFlow) | `DeepExplainer`, `GradientExplainer` | 그래디언트 기반 **근사**. 비교적 빠름 |
| 아무 모델 (SVM, kNN, 파이프라인 전체 등) | `KernelExplainer`, `PermutationExplainer` | 피처를 바꿔 넣으며 예측을 여러 번 호출해 **근사.** 느리다 → 행·배경 데이터를 샘플링해서 쓴다 |

`shap.Explainer(model, X_background)`를 쓰면 모델 종류를 보고 알맞은 방법을 자동으로 고른다.

#### 선형 모델의 SHAP

피처끼리 독립이라고 보면, 선형 모델의 SHAP은 계산 없이 식으로 나온다.

```
SHAP_i = w_i × (x_i − 평균 x_i)
```

예: `집값 = 1.0 + 0.05 × 면적(㎡)`, 평균 면적 80㎡, 이 집 96㎡
→ 면적 SHAP = 0.05 × (96 − 80) = **+0.8억**

- 계수 w만 보면 "면적이 중요하다"만 알 수 있지만, SHAP은 **이 행의 값이 평균에서 얼마나 떨어져 있는지**까지 곱해서 행별 기여로 바꿔 준다.
- 로지스틱 회귀면 같은 식이 log-odds 단위로 성립한다.

#### 비선형 모델에서 주의

- 근사 Explainer(Kernel, Permutation, Deep)는 **결과가 샘플링·배경 데이터에 따라 조금씩 흔들린다.** 배경 데이터는 학습 데이터에서 수백~천 행 정도 뽑아 쓴다.
- 배경 데이터가 곧 "기준값"을 정하므로, **어떤 데이터를 배경으로 썼는지**에 따라 SHAP의 의미가 달라진다 (예: 정상 거래만 배경 → "정상 거래 대비" 기여).

---

### 7. 그룹별 평균 SHAP 읽는 법

그룹(예: 잡힌 사기 / 놓친 사기 / 정상)마다 **각 행의 SHAP 값을 구한 뒤 그룹 안에서 평균**한 표를 자주 쓴다.

| 놓친 사기 행 | CVV 재입력 횟수 SHAP |
|---|---|
| 행 1 | +1.20 |
| 행 2 | 0.00 |
| 행 3 | +0.30 |
| 행 4 | −0.05 |
| 행 5 | +0.55 |
| **평균** | **+0.40** |

- **부호 있는 평균**: 그 그룹에서 피처가 **어느 방향으로** 밀었는지. +와 −가 상쇄되므로 평균 0이 "영향 없음"을 뜻하지는 않는다.
- **\|SHAP\| 평균** (bar plot): 방향과 무관하게 **얼마나 크게** 영향을 줬는지.
- 평균은 분포를 숨긴다. **SHAP > 0인 행의 비율, 중앙값**을 함께 본다.

#### 사례: 사기 탐지 (LightGBM, 검증 fold 기준, 기준선 22%)

| 피처 | 잡힌 사기 | 놓친 사기 | 정상 |
|---|---|---|---|
| CVV 재입력 횟수 | +1.71 | +0.40 | −0.02 |
| 가맹점 위험 점수 | +1.21 | +0.69 | −0.01 |
| 거래 속도 점수 | +0.97 | +0.55 | −0.02 |
| 인증 방식 | +0.78 | +0.32 | −0.01 |
| IP 국가 불일치 | +0.53 | +0.08 | −0.01 |

- 놓친 사기도 같은 피처들이 + 방향으로 밀지만 크기가 잡힌 사기의 1/4~1/2 수준이다. **신호가 없는 게 아니라 약하거나 하나뿐이라서** 여러 신호가 겹쳐야 넘는 기준선을 못 넘었다.
- 놓친 사기에서 예측을 가장 많이 내린 피처(처음 거래하는 가맹점 아님, 인증을 거침 등)는 **정상이라는 강한 증거가 아니라 사기 신호가 없다는 뜻**이다.
- 정상 행이 거의 0인 이유: 정상이 98%라 기준값 자체가 정상 거래에 맞춰져 있다.

**해석할 때 주의**

- "잡힌 / 놓친"은 **예측값(= SHAP의 합)으로 나눈 그룹**이라, 잡힌 쪽 SHAP이 큰 것은 정의상 당연하다. 의미 있는 정보는 **피처 간 상대적 차이** (CVV 1.31 차이, IP 국가 불일치 약 7배)다.
- 차이가 **피처 값 자체에서 오는지** 원본 값을 함께 본다. 놓친 사기의 CVV 재입력이 정상처럼 대부분 0이면 모델이 아니라 **정보가 없는 문제** → 오차 분석 2-2의 "모두 같이 틀림 → 데이터 수정".
- "신호가 전혀 없는 행" 같은 지표는 **정의(예: 모든 SHAP ≤ 0)를 함께 적는다.**

**다음 행동으로 연결**

1. threshold 조정: PR 곡선으로 기준선을 낮출 때 recall·오탐 변화 확인
2. 단일 신호 + 맥락의 상호작용 피처 (예: CVV 재입력 1회 × 처음 거래하는 가맹점)
3. 두 모델의 SHAP 순위가 비슷하면 → 같은 정보를 같은 방식으로 쓰는 것이므로 잔차 상관이 높은 이유가 설명된다. 앙상블보다 **새 정보(피처) 추가**가 효과적이다.

---

### 8. 함정

- **상관 높은 피처끼리 기여를 나눠 가진다.** "결제 금액"과 "원화 환산 금액"처럼 거의 같은 피처는 SHAP이 쪼개져 둘 다 덜 중요해 보인다. 하나를 빼면 다른 쪽이 그만큼 커진다.
- **인과관계가 아니다.** "이 피처를 바꾸면 결과가 바뀐다"가 아니라 **"이 모델이 이 피처를 이렇게 사용했다"**이다.
- **모델이 틀렸으면 틀린 이유를 설명한다.** 정답과 무관하게 모델의 판단 근거만 보여 준다.
- **학습에 쓴 행이 아니라 검증(OOF) 행으로 계산한다.** 학습 행에서는 외운 패턴까지 설명하게 된다.

## 회고

- 처음에는 스태킹을 "폴드마다 meta model에 넣어 예측한다"로 이해했지만, 실제로는 **OOF 예측을 모두 모은 뒤 meta model을 한 번 학습**하는 구조였다.
- fold 학습은 meta model 학습 데이터를 만드는 용도이고, 실제 예측에 쓰는 base model은 **train 전체로 다시 학습**한다는 역할 구분이 핵심이었다.
- 같은 train 데이터로 예측값을 만들면 meta model이 과적합된다는 점은 ASHRAE에서 겪은 **"검증 방식이 실제 조건과 맞아야 한다"**는 교훈과 같은 맥락이다.
- 다음 프로젝트에서는 단순 가중 평균(블렌딩)과 스태킹을 같은 교차검증 조건에서 비교해 보고, 복잡도 대비 이득이 있는지 확인한다.
- 처음에는 예측 상관만 봤는데, 정리하면서 오차 상관을 계산해 보니 판단이 훨씬 분명해졌다. 예측 상관은 0.92~0.995 로 모두 비슷해 보였지만 오차 상관은 0.52 부터 0.95 까지 벌어졌다. 앙상블을 설계할 때는 처음부터 오차 상관 표를 만든다.
- 오차 분석의 핵심은 "누가 틀리나"를 구분하는 것이었다. 한 모델만 틀리면 모델을, 모두 같이 틀리면 데이터를 고친다. 이 구분 없이 튜닝이나 모델 추가부터 하면 시간 대비 효과가 작았다.
- 교차검증으로 보이지 않는 문제(학습 범위 밖 입력, 검증과 평가 조건의 차이)가 두 프로젝트 모두에서 실제 점수를 크게 좌우했다. 오차 분석은 학습 데이터 안의 문제만 보여 준다는 한계를 기억하고, 평가 데이터 점검을 별도 단계로 둔다.
- 사기 탐지 모델의 잔차 상관 표를 해석하면서, 상관은 **오차의 크기가 아니라 "같이 움직이는지"**를 본다는 점을 다시 정리했다. 전체 행으로 계산한 상관은 클래스 간 차이 때문에 부풀려지므로, 불균형 분류에서는 클래스별로 나눠 보고 피어슨과 스피어만을 함께 비교한다.
- SHAP을 정리하면서, 그룹별 평균 SHAP 비교는 "잡힌 / 놓친"을 예측값으로 나눈 이상 차이가 나는 게 당연하다는 점을 알게 됐다. 크기 자체보다 **피처 간 상대적 차이와 원본 피처 값**을 같이 봐야 모델 문제인지 정보 부족인지 구분할 수 있다. 또 log-odds +0.7은 확률이 아니라 **오즈 2배**라서, 기준선 근처에서는 "확률 2배"로 말하면 틀린다.
