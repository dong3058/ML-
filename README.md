## 앙상블 (Ensemble)

**여러 모델의 예측 결과를 합쳐서 최종 예측을 만드는 방법.**

핵심은 **서로 다른 실수를 하는 모델을 섞는 것**이다.

- LightGBM, XGBoost, CatBoost는 모두 트리 계열이라 틀리는 패턴이 비슷하다. 그래서 이들끼리 섞으면 효과가 작다.
- 선형 모델 + 트리 모델처럼 **성격이 다른 모델**을 섞으면 서로의 약점을 보완해서 효과가 크다.

> 참고: Random Forest(배깅)나 XGBoost(부스팅)도 내부적으로는 여러 트리를 합치는 앙상블이다.
> 이 문서의 방법들은 **이미 완성된 서로 다른 모델들을 바깥에서 합치는 방법**이다.

### 1. 평균 (Averaging)

회귀 문제에서 주로 사용한다.

| 모델 | 집값 예측 |
|---|---|
| 선형 회귀 | 5.0억 |
| LightGBM | 5.4억 |
| CatBoost | 5.3억 |
| **단순 평균** | **(5.0 + 5.4 + 5.3) / 3 = 5.23억** |

**가중 평균**: 성능이 좋은 모델에 더 큰 비중을 준다.

```
최종 = 0.2 × 5.0 + 0.4 × 5.4 + 0.4 × 5.3 = 5.28억
```

가중치는 검증(validation) 데이터에서 성능이 가장 좋은 조합으로 정한다.

### 2. 투표 (Voting)

분류 문제에서 주로 사용한다.

**Hard voting**: 각 모델이 낸 클래스로 다수결을 한다.

| 모델 | 예측 |
|---|---|
| 모델 A | 스팸 |
| 모델 B | 정상 |
| 모델 C | 스팸 |
| **결과** | **스팸 (2:1)** |

**Soft voting**: 각 모델이 낸 **확률을 평균**해서 결정한다. 보통 이쪽이 성능이 더 좋다.

| 모델 | 스팸일 확률 |
|---|---|
| 모델 A | 0.9 |
| 모델 B | 0.4 |
| 모델 C | 0.6 |
| **평균** | **0.63 → 스팸** |

Hard voting은 0.51과 0.99를 똑같이 한 표로 친다. Soft voting은 **모델이 얼마나 확신하는지**까지 반영한다.

### 3. 스태킹 (Stacking)

**여러 모델의 예측값을 입력으로 받아서 최종 답을 내는 모델을 하나 더 학습시키는 방법.**

"어떻게 합칠지"를 사람이 정하지 않고 모델이 학습한다. 자세한 내용은 아래에 정리했다.

---

## 스태킹 상세

### 비유

전문가 3명에게 집값을 물어보는 상황을 생각해 보자.

- **평균**: 세 명의 의견을 그냥 평균 낸다.
- **가중 평균**: "B가 제일 정확하니 B 의견을 40% 반영하자"처럼 사람이 비중을 정한다.
- **스태킹**: **팀장을 한 명 둔다.** 팀장은 과거 기록을 보면서 "A는 아파트는 잘 맞히는데 단독주택은 자주 틀린다", "B와 C 의견이 같으면 거의 맞는다" 같은 패턴을 **스스로 학습**한다. 그리고 세 명의 의견을 듣고 최종 판단을 내린다.

여기서 전문가 = **base model (1단계)**, 팀장 = **meta model (2단계)**.

### 구조

```
원본 feature (나이, 소득, 지역 ...)
        │
        ├──→ 선형 회귀  ──→ 예측 p1 ┐
        ├──→ LightGBM   ──→ 예측 p2 ├──→ [meta model] ──→ 최종 예측
        └──→ CatBoost   ──→ 예측 p3 ┘
```

meta model 입장에서는 **입력 feature가 `p1, p2, p3` 3개인 평범한 모델**이다.

| p1 (선형) | p2 (LGBM) | p3 (Cat) | 정답 y |
|---|---|---|---|
| 5.0 | 5.4 | 5.3 | 5.35 |
| 3.1 | 2.8 | 2.9 | 2.85 |
| ... | ... | ... | ... |

- meta model이 선형 회귀라면 `y = w1·p1 + w2·p2 + w3·p3 + b`를 학습한다. 가중 평균의 가중치를 **데이터에서 자동으로 찾는 것**과 비슷하다.
- meta model로 트리 모델을 쓰면 "p1과 p2의 차이가 클 때는 p2를 믿어라" 같은 조건부 판단도 학습할 수 있다.

### Out-of-Fold (OOF) 예측

#### 잘못된 방법

base model을 train 데이터 전체로 학습한 뒤, **같은 train 데이터를 예측**해서 `p1, p2, p3`를 만드는 방법이다.

- base model은 이미 본 데이터를 맞히기 때문에 예측이 정답과 거의 같다. 특히 트리 모델은 거의 외워버린다.
- 그러면 meta model은 "LightGBM은 항상 정확하다"고 잘못 학습한다.
- 결과적으로 새 데이터에서 성능이 떨어진다. **(과적합)**

#### 올바른 방법: K-Fold OOF 예측

train 데이터(예: 1000행)를 5개 fold(각 200행)로 나눈다.

```
train 데이터 1000행 (정답 y 있음)
┌──────┬──────┬──────┬──────┬──────┐
│fold1 │fold2 │fold3 │fold4 │fold5 │
└──────┴──────┴──────┴──────┴──────┘
  예측     ←────── 학습 ──────→        (1회차)
```

| 회차 | 학습 데이터 | 예측 대상 | 결과 |
|---|---|---|---|
| 1 | fold 2~5 (800행) | fold 1 (200행) | 1~200행의 p1 |
| 2 | fold 1,3,4,5 | fold 2 | 201~400행의 p1 |
| 3 | fold 1,2,4,5 | fold 3 | 401~600행의 p1 |
| 4 | fold 1,2,3,5 | fold 4 | 601~800행의 p1 |
| 5 | fold 1~4 | fold 5 | 801~1000행의 p1 |

- 5번을 돌면 **1000행 전체에 대한 p1 컬럼**이 완성된다.
- 각 행의 예측값은 **그 행을 학습에 쓰지 않은 모델**이 만든 값이다. 그래서 실제 새 데이터를 만났을 때의 예측과 성질이 비슷하다.
- 예측 대상 fold도 원래 train 데이터의 일부라서 **정답 y를 알고 있다**. 따라서 각 행마다 **(모델 예측값, 실제 정답)** 쌍이 생기고, 이게 meta model의 학습 데이터가 된다.
- 같은 과정을 LightGBM(→ p2), CatBoost(→ p3)에도 반복한다.

**왜 이렇게 하나?**
meta model이 배워야 하는 건 **"base model이 처음 보는 데이터에서 어떻게 틀리는지"**다. 이걸 배우려면 두 가지가 동시에 필요하다.

1. base model이 **안 본 데이터**에 대한 예측
2. 그 데이터의 **정답**

test 데이터는 최종 평가용이라 건드리면 안 된다. 그래서 **train 데이터 안에서 일부를 가려 놓고 "안 본 데이터" 역할을 시키는 것**이다.

### 전체 학습 흐름

1. **OOF 예측 생성**: 각 base model을 K-Fold로 학습하고, fold별 예측을 모아 `p1, p2, p3` 컬럼을 만든다.
   → 이 단계의 fold 모델들은 **meta model 학습 데이터를 만드는 용도**일 뿐이다.
2. **meta model 학습 (1번)**: `(p1, p2, p3) → y` 표 전체로 meta model을 한 번 학습한다.
3. **base model 재학습**: 각 base model을 **train 전체(1000행)로 다시 학습**한다. 800행보다 1000행으로 학습한 모델이 더 좋기 때문이다.
4. **실제 예측**:
   ```
   새 데이터 → base model 3개 (3단계) → p1, p2, p3 → meta model (2단계) → 최종 예측
   ```

| 대상 | 학습 횟수 | 용도 |
|---|---|---|
| base model (OOF용) | 3 × 5 = 15번 | meta model 학습 데이터 생성 |
| meta model | 1번 | 섞는 방법 학습 |
| base model (최종) | 3번 | 실제 예측용 |

> **변형**: 3단계에서 재학습하지 않고, 새 데이터에 대해 **fold 모델 5개의 예측을 평균**해서 쓰는 방식도 있다. Kaggle에서 자주 쓰며, 재학습 비용을 아끼고 예측이 안정되는 장점이 있다.
> scikit-learn의 `StackingClassifier`/`StackingRegressor`는 전체 데이터로 재학습하는 방식으로 동작한다.

### 데이터 역할 정리

| 데이터 | 정답 | 쓰임 |
|---|---|---|
| train (5개 fold) | 있음 | base model 학습 + OOF 예측 생성 → meta model 학습 |
| test | 평가 때만 사용 | 완성된 스태킹 전체의 최종 성능 확인 |

OOF 과정은 **전부 train 데이터 안에서만** 일어난다. test 데이터는 마지막까지 손대지 않는다.

### 실무 팁

- **meta model은 단순하게**: 보통 Linear/Logistic Regression이나 Ridge를 쓴다. 입력이 몇 개 안 되기 때문에 복잡한 모델을 쓰면 오히려 과적합된다.
- **base model은 다양하게**: 선형 + 트리 + (가능하면) KNN이나 신경망처럼 성격이 다를수록 효과가 크다.
- **비용**: 학습 시간이 `base model 수 × fold 수`만큼 늘고 구조도 복잡해진다. Kaggle처럼 0.1%가 중요한 곳에서는 많이 쓰지만, 실무에서는 단순 평균으로 충분한 경우도 많다.

## 사용 도구

- scikit-learn의 `VotingClassifier` / `VotingRegressor`: `voting="soft"`로 soft voting
- scikit-learn의 `StackingClassifier` / `StackingRegressor`: `cv=5`를 주면 OOF 예측 → meta model 학습 → base model 전체 재학습을 자동으로 처리
- 이 저장소의 [`house-prices-advanced-regression-techniques`](house-prices-advanced-regression-techniques/README.md)는 CatBoost + LightGBM + Lasso를 **가중 평균(블렌딩)**으로 합쳤다. 선형(Lasso) + 트리 모델을 섞은 사례다.

## 요약

| 방법 | 주 사용처 | 합치는 방식 |
|---|---|---|
| 평균 / 가중 평균 | 회귀 | 예측값을 (가중) 평균 |
| Hard voting | 분류 | 클래스 다수결 |
| Soft voting | 분류 | 확률 평균 |
| Stacking | 회귀·분류 | meta model이 합치는 방법을 학습 |

- 회귀는 **평균이나 가중 평균**, 분류는 **soft voting**이 기본이다.
- 성능을 최대로 끌어올리려면 **stacking**을 쓴다. 단, **out-of-fold 예측은 필수**다.
- 스태킹 한 줄 요약: **여러 모델의 예측을 어떻게 섞을지 자체를 또 다른 모델이 학습하는 앙상블.**

## 회고

- 처음에는 스태킹을 "폴드마다 meta model에 넣어 예측한다"로 이해했지만, 실제로는 **OOF 예측을 모두 모은 뒤 meta model을 한 번 학습**하는 구조였다.
- fold 학습은 meta model 학습 데이터를 만드는 용도이고, 실제 예측에 쓰는 base model은 **train 전체로 다시 학습**한다는 역할 구분이 핵심이었다.
- 같은 train 데이터로 예측값을 만들면 meta model이 과적합된다는 점은 ASHRAE에서 겪은 **"검증 방식이 실제 조건과 맞아야 한다"**는 교훈과 같은 맥락이다.
- 다음 프로젝트에서는 단순 가중 평균(블렌딩)과 스태킹을 같은 교차검증 조건에서 비교해 보고, 복잡도 대비 이득이 있는지 확인한다.
