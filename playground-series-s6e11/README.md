# Playground Series S6E11 – Predicting Credit Card Fraud

[Kaggle 대회](https://www.kaggle.com/competitions/playground-series-s6e11): 카드 거래 한 건이 사기인지(`is_fraud`) 확률로 예측한다. 마감 2026-11-30.

- **평가 지표:** ROC AUC. 모든 거래를 예측 확률 순으로 세웠을 때 사기가 정상보다 위에 오는 비율이다. 확률의 크기가 아니라 순서만 평가하므로, 기준선(몇 % 이상을 사기로 볼지)을 바꿔도 점수는 그대로다.
- **기준선:** 무작위 예측은 0.5, 1.0이면 모든 사기가 모든 정상보다 위에 온다.

**최고 점수**

| 구분 | 버전 | 5-fold OOF AUC | Kaggle Public |
|---|---|---|---|
| 정석 (실무에서도 쓸 수 있는 방법만) | v7 LightGBM 튜닝 | 0.94754 | **0.94788** |
| 대회 전용 (합성 데이터의 흔적까지 이용) | v10 v7 + 값·자릿수 타깃 인코딩 | 0.94986 | **0.95104** |

v10은 실제 사기 패턴이 아니라 합성 데이터를 만드는 과정에서 생긴 흔적을 이용한다. 그래서 정석과 분리해 기록한다 (3장 v10, 6장).

## 2. 데이터 가공 흐름

```
train.csv / test.csv
  │
  ├─ 1) 공통 전처리
  │     범주형 5개 → LightGBM 범주형으로 직접 사용 (선형·MLP 는 원-핫)
  │     True/False 6개 → 0/1
  │     숫자형 13개 → 그대로 (선형·MLP 만: 꼬리가 긴 6개 log1p + 표준화)
  │
  ├─ 2) 검증 분할
  │     StratifiedKFold 5-fold (random_state=42), 사기 비율을 fold 마다 유지
  │     모든 버전이 같은 분할을 써서 fold 별로 직접 비교
  │
  ├─ 3) 모델 학습 (fold 마다)
  │     LightGBM: 검증 fold AUC 기준 early stopping 200
  │     테스트 예측 = 5개 fold 모델 예측의 평균
  │
  ├─ 4) (v10 계열만) 구간·값별 타깃 인코딩
  │     키 만들기: 정수 부분, 20분위, 나이 5세 구간, 값 그대로, 센트, 앞 두 자리 …
  │     학습 행: 학습 부분 안에서 다시 5-fold 로 나눠 자기 fold 를 뺀 나머지로 계산
  │     검증·테스트 행: 학습 부분 전체로 계산
  │     평활: (사기 수 + 20 × 전체 사기율) / (행 수 + 20)
  │
  └─ 5) 평가·분석
        OOF 예측으로 AUC, fold 별 변화, 오차 분석, SHAP, 오차 상관
        제출은 버전별로 Kaggle Public 점수 확인
```

v4·v6의 비교 기준은 early stopping 없이 669회로 고정한 LightGBM(0.94661)이다.

### v1~v2: 선형 기준 모델
- 꼬리가 긴 컬럼(`log1p`)의 효과는 +0.0003으로 작았다. 변환한 컬럼들이 원래 사기와 관련이 약했다.
- 오차 분석에서 `velocity_score`, `txn_count_last_24h`, `merchant_risk_score`, `customer_age` 네 변수가 곡선 관계라 직선으로 맞추지 못했다. 예: 거래 속도 4.1 이하 구간에서 예측이 실제의 2.5배.

### v3: LightGBM
- 위 네 변수의 구간별 예측/실제 비율이 0.21~0.26 벗어나던 것이 0.02~0.04로 줄었다. 곡선 관계를 트리가 잡았다.
- 선형과 LightGBM의 오차 상관이 0.979(사기 행 0.956)로 매우 높았다. 둘이 같은 사기를 함께 놓쳤고, 순위 평균 블렌드도 +0.00015뿐이었다.

### 놓친 사기 분석 (v2·v3 공통으로 놓친 5,520건)
- 실제 사기 수(11,689)만큼 상위를 지목했을 때 두 모델 모두 놓친 사기다. 평균 예측 확률 5.9% (잡힌 사기 64.2%, 정상 1.1%).
- 모든 피처에서 정상과 잡힌 사기 사이에 있다. 놓친 사기만 다른 피처는 없다.
- SHAP: 잡힌 사기와 같은 피처가 같은 방향으로 올리지만 크기가 작다. 새로운 유형이 아니라 신호가 약한 사기다.
- 위험 신호 개수 평균: 정상 0.39, 놓친 사기 1.07, 잡힌 사기 2.66.
- SHAP 벡터로 군집화하면 5유형: 약한 신호 묶음형(43%), CVV 1회 재입력형, 무인증형, 고위험 업종형, 청구·배송지 불일치형. 유형마다 강한 신호가 하나뿐이고, 같은 모양의 정상 거래가 사기 1건당 24~230건이다.

### v4~v6: 애매한 구간 보정
- 놓친 사기가 몰린 확률 구간만 따로 선형 모델이나 MLP로 학습해 섞었다.
- 구간 안 AUC에서도 LightGBM이 더 높았다 (선형 −0.02, MLP −0.04~−0.07). 섞어서 얻은 것은 최대 +0.0001이다.
- MLP는 정확도 기준 early stopping이 불균형 데이터에서 쓸모가 없어 고정 epoch로 학습했고, 과적합으로 단독 0.918에 그쳤다.

### v7: Optuna 튜닝 (60회, 3-fold 탐색 → 5-fold 확인)
- 5개 fold 모두 +0.0006~+0.0010 올랐다. Public 0.94788로 OOF와 0.0003 차이다.
- 선택된 설정은 작은 트리를 많이 쌓는 쪽이다: `num_leaves` 10, `max_depth` 5, `min_child_samples` 994, `feature_fraction` 0.37, 평균 1,409회. 신호가 약하고 잡음이 많아 복잡한 트리는 잡음을 외웠다.

### v8: B 피처 전문 모델 스태킹
- B 피처만 쓰는 LightGBM(S1), A 신호 없는 행만 학습한 LightGBM(S2), 스플라인 로지스틱(S3)을 만들었다. 모두 본 모델보다 낮았다.
- 스태킹 OOF +0.00025(5/5 fold)였지만 Public은 −0.0003. 효과는 S1과 S3의 차이(B 피처끼리의 조합 신호)에서만 나왔고, 흔들림에 묻히는 크기였다.

### v9: 놓친 사기 5유형 전문 모델
- 5유형을 정답 없이 쓸 수 있는 규칙으로 다시 정의하고, 구간마다 LightGBM을 따로 학습했다.
- 5유형 모두 구간 안에서 본 모델이 더 높았다. 학습할 사기가 306~2,048건으로 줄었기 때문이다.
- 가중치를 같은 데이터로 고르면 +0.00004, 한 fold를 빼고 고른 가중치를 빠진 fold에 적용한 정직한 추정은 ±0.

### v10: 값·자릿수 타깃 인코딩 (대회 전용)
- 공개 저장소들이 공통으로 쓰는 "값이나 자릿수별 사기율" 피처를 넣었다. 원래 의미가 없어야 할 센트 단위 같은 값에도 사기가 몰려 있다.
- 효과를 나눠 보니 v10의 +0.0023 중 정석으로 설명되는 부분은 +0.0003(v10-a′)뿐이고, 나머지 약 +0.002는 합성 데이터의 흔적이다.
  - v10-a(+0.0010)는 "앞 두 자리"(7.5와 75를 한 구간으로 묶음)와 나이 1세 단위가 들어가 정석이 아니었다. 이 둘을 빼자(v10-a′) +0.0003으로 줄었다.
  - 센트 단위와 무관 피처만 넣은 v10-c도 +0.0010, 5/5 fold 상승이었다.
- v10 Public 0.95104 (v7 대비 +0.0032).

## 4. 오차 분석과 의사결정

| 관찰 | 판단 | 다음 행동 |
|---|---|---|
| 선형 모델이 특정 변수의 양 끝에서 2배 넘게 틀림 | 곡선 관계 (모델 구조 문제) | 트리 모델(v3) |
| 선형과 LightGBM의 오차 상관 0.96 | 같은 행에서 함께 틀림, 섞어도 효과 없음 | 놓친 사기 분석 |
| 놓친 사기가 모든 피처에서 정상과 잡힌 사기 사이 | 신호가 약한 것이지 모르는 유형이 아님 | 구간 보정·전문 모델은 기대가 작음 |
| 전문 모델이 자기 구간에서도 본 모델보다 낮음 | 구간을 좁히면 학습할 사기가 부족 | v7 유지 |
| 내부 +0.00025가 Public −0.0003 | 가중치 선택의 낙관 편향 | 이후 "한 fold 빼고 고르기"로 판단 (v9) |
| 센트 단위 사기율이 점수를 올림 | 합성 데이터의 흔적 | 정석과 대회 전용 분리 (v10) |

**민감도(기준선)에 대하여:** 기준선을 22%에서 5%로 낮추면 재현율은 49.5% → 73.4%로 오르지만 오탐이 5,565 → 30,220건으로 늘어난다 (사기 1건 더 잡을 때 정상 약 9건). 놓친 사기가 가진 "신호 1개" 패턴을 정상 거래 약 23만 건도 가지고 있기 때문이다. AUC는 기준선과 무관하므로 대회 점수에는 영향이 없고, 실제 서비스에서 비용을 저울질해 정할 문제다.

**데이터 양에 대하여:** 전문 모델이 약했던 것은 데이터 부족 때문이라 데이터가 늘면 나아진다. 하지만 "같은 모양인데 정답이 다른" 놓친 사기는 행을 늘려도 구별되지 않고, 새로운 종류의 정보(카드 거래 이력 등)가 필요하다. 원본 데이터는 2만 행(사기 339건)으로, 학습 데이터를 늘리는 용도로는 작다.

## 5. 구간 타깃 인코딩 (v10-a′에 적용한 기법)

숫자 피처를 구간으로 나누고, 각 구간의 과거 사기율을 새 피처로 추가하는 방법이다.

### 절차
1. **구간 정하기 (정답 사용 안 함).** 업무적으로 설명되는 구간만 쓴다.
   - 정수 부분: 가맹점 위험 점수 34.2 → "34점대"
   - 20분위: 값 크기 순으로 행 수가 같은 20개 구간. 경계는 학습 데이터 분포로만 정한다
   - 나이 5세 구간, 24시간 거래 수는 값 그대로
2. **구간별 사기율 계산.** 행이 적은 구간은 사기율이 크게 흔들리므로 전체 사기율 쪽으로 당긴다.
   - 인코딩 값 = (구간의 사기 수 + m × 전체 사기율) / (구간의 행 수 + m), m = 20
   - 행이 20개인 구간은 자기 사기율과 전체 사기율을 반반 섞은 값이 된다. 행이 많을수록 자기 사기율에 가까워진다
   - 처음 보는 구간은 전체 사기율을 쓴다
3. **누수 막기 (중첩 계산).** 자기 정답이 자기 피처에 들어가면 학습 점수만 높아지고 실제 성능은 떨어진다.
   - 바깥 5-fold 마다, 학습 행의 인코딩은 학습 부분 안에서 다시 5-fold로 나눠 자기 fold를 뺀 나머지로 계산한다
   - 검증 행과 테스트 행은 학습 부분 전체로 계산한다
4. **원래 피처와 함께 모델에 넣는다.** 원래 값도 유지한다.

### 언제 효과가 있나
- 모델이 곡선 관계를 세밀하게 표현하지 못할 때다. 선형 모델이나 잎이 적은 트리가 해당한다.
- 이번에는 v7 트리(잎 10개)가 이미 원래 피처로 곡선을 충분히 잡고 있어서 +0.0003에 그쳤다.

### 주의할 점
- **구간이 의미를 가져야 한다.** "앞 두 자리"는 7.5와 75, 3.42와 34.2를 같은 구간으로 묶는다. 업무적으로 설명이 안 되는 구간은 데이터의 우연한 흔적을 잡는다.
- **너무 잘게 나누지 않는다.** 값 하나하나(나이 1세, 금액 1센트)를 구간으로 쓰면 들쭉날쭉한 잡음이나 생성 과정의 흔적을 외운다. 카드 사용 기간은 49개월 1.90%, 51개월 1.43%처럼 이웃 값끼리 크게 엇갈렸다.
- **반드시 fold 안에서 계산한다.** 전체 데이터로 한 번에 계산하면 검증 점수가 부풀려진다.
- **실제 서비스에서는** 과거 기간 데이터로 사기율을 계산해 이후 거래에 적용하고, 주기적으로 다시 계산한다.

## 8. 회고

- **분석이 "무엇을 하지 말아야 하는지"를 알려 줬다.** 오차 상관 0.96, 놓친 사기의 피처 위치, SHAP 비교가 모두 "신호가 약한 사기"라는 같은 결론을 가리켰다. 그 뒤의 구간 보정, MLP, 전문 모델, 유형별 모델 네 번이 모두 효과가 없었던 것도 같은 이유다. 분석 결과를 더 믿었다면 실험 몇 개를 줄일 수 있었다.
- **모델 교체(선형 → LightGBM, +0.0047) 다음으로는 튜닝이 정석 방법 중 가장 큰 개선이었다 (+0.0009).** House Prices 때와 같이 "작고 강하게 규제된 트리"가 이겼다. 잡음이 많은 데이터에서는 모델을 키우는 것보다 덜 외우게 하는 것이 낫다.
- **내부 점수 +0.00025는 믿을 수 없는 크기였다.** v8은 5/5 fold 상승이었는데도 Public에서 떨어졌다. 가중치를 같은 OOF로 고르는 낙관 편향이 원인이다. v9부터는 "한 fold 빼고 고른 가중치를 빠진 fold에 적용"한 정직한 추정으로 판단했고, 그 값이 0이었다.
- **합성 데이터에서는 데이터의 흔적이 실제 패턴보다 큰 신호일 수 있다.** v10 개선의 대부분(+0.002)이 센트 단위나 자릿수 같은 의미 없는 값에서 나왔다. 처음에는 "앞 두 자리"를 정석으로 분류했다가, 효과를 하나씩 분해하고서야 흔적이라는 걸 알았다. 기법을 가져올 때는 그 기법이 무엇을 잡는지부터 확인해야 한다.
- **정석과 대회 전용을 분리해 기록했다.** 점수만 쫓으면 무엇이 실제로 일반화되는 지식인지 흐려진다. 정석 최종은 v7(Public 0.94788), 대회 제출용은 v10(Public 0.95104)이다.
- **AUC는 기준선과 무관하다.** 민감도를 높이자는 아이디어는 실무에서는 유효하지만, 순위를 바꾸지 않으면 대회 점수는 그대로다. 평가 지표가 무엇을 재는지부터 정리하고 시작해야 한다.
- **아쉬운 점:** MLP를 검증 AUC 기준 early stopping 없이 돌려 비선형 모델 비교가 불완전했다. 실행 중간에 변수 이름 실수로 10분짜리 실행을 다시 돌렸다. MLflow 기록 없이 로그 파일로만 남겼다.
- **다음에 해 볼 것:** 학습 곡선(데이터 양에 따른 AUC)으로 데이터 부족 여부를 먼저 확인하기, CatBoost·XGBoost 다중 seed 평균, 처음부터 "정직한 추정"으로 앙상블 가중치를 고르는 공통 함수 만들기.
