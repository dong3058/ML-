# House Prices – Advanced Regression Techniques

[Kaggle 대회](https://www.kaggle.com/competitions/house-prices-advanced-regression-techniques): 미국 아이오와주 Ames 시의 주택 79개 속성으로 판매 가격(`SalePrice`)을 예측한다.

- **평가 지표:** log(예측 가격)과 log(실제 가격) 사이의 RMSE. 비싼 집과 싼 집의 오차를 같은 비율로 평가한다.
- **점수 해석:** RMSE 0.13 ≈ 예측이 평균적으로 실제 가격의 약 ±14% 범위. 0.12967이면 오차 배율 e^0.12967 ≈ 1.138.
- **기준선:** 모든 집을 평균 가격 하나로 예측하면 RMSE ≈ 0.40 (학습 데이터 log 가격의 표준편차).

**현재 최고 점수: Kaggle 0.11870** (v7: CatBoost + LightGBM + Box-Cox Lasso 블렌딩, 학습 범위 밖 집 보호 장치). 교차검증 0.1078.
처음 제출(0.13585)보다 0.0172 개선 — 오차율 약 ±14.6% → ±12.6%. 공개 리더보드 상위 약 8%.

## 2. 데이터 가공 흐름

```
train.csv / test.csv
  │
  ├─ 1) 결측 해석
  │     'NA' 문자열 = "시설 없음" (예: PoolQC=NA → 수영장 없음) → 카테고리 값 'NA' 로 유지
  │     진짜 빈 칸만 결측으로 처리
  │
  ├─ 2) 이상치 제거 (train 만)
  │     Id 524, 1299: 거주 면적 4,000 sq ft 초과인데 가격 30만 달러 미만 → 제외 (1,458행)
  │
  ├─ 3) 수치형 결측 채우기 (채움 기준값은 train 에서만 계산)
  │     LotFrontage(도로 접면 길이) → 같은 동네 중앙값
  │     GarageYrBlt(차고 건축 연도) → 건축 연도
  │     나머지 (지하·차고·외장 면적 등) → 0 (시설 없음)
  │
  ├─ 4) 파생 피처 16개
  │     합계   : TotalSF(지하+1층+2층), TotalBath(반욕실 0.5), TotalPorchSF
  │     나이   : HouseAge(판매 시 집 나이), RemodAge(리모델링 후 경과), IsRemodeled, IsNew
  │     유무   : HasPool, Has2ndFlr, HasGarage, HasBsmt, HasFireplace
  │     상호작용: QualTotalSF(품질×총면적), QualGrLiv(품질×거주면적), OverallGrade(품질×상태)
  │     품질합 : QualSum (외장·주방·지하·차고·난방·벽난로 품질 점수 합)
  │
  ├─ 5) 정답 변환: log1p(SalePrice) — 평가 지표와 맞추고 치우친 분포를 펴기 위해
  │
  ├─ 6) 모델별 입력 (v1~v4: 역할 분담 / v5~: 피처 공유)
  │     CatBoost : 카테고리 44개            → v5 부터 + 수치형 51개
  │     수치형 모델: 수치 35 + 파생 16 = 51개 → v5 부터 LightGBM 에 품질 등급 10개(숫자)
  │                                              + SaleCondition·MSZoning·Neighborhood·Functional
  │     선형 모델 (v7): 수치형 51개 Box-Cox + 카테고리 44개 원-핫 → RobustScaler → Lasso
  │
  ├─ 7) 반복 5-fold × 3 교차검증 → 모델별 교차검증 예측(OOF)
  │
  ├─ 8) 스태킹: OOF 예측들 → 메타 모델 (가중치 ≥ 0 인 선형회귀)
  │     메타 모델 점수는 OOF 위에서 다시 5-fold 로 검증
  │
  ├─ 9) 기본 모델을 train 전체로 재학습 → test 예측 → 메타 모델로 결합
  │
  └─ 10) 보호 장치 (v4-B, v7): 수치형 피처가 하나라도 학습 범위 밖인 test 집(23채)은
         선형·신경망 모델을 뺀 예측 사용 → expm1 → 제출
```

### 공통 기법과 이유
| 기법 | 이유 |
|---|---|
| `NA` 문자열을 카테고리 값으로 유지 | `PoolQC=NA` 는 결측이 아니라 "수영장 없음"이라는 정보 |
| 이상치 2채 제거 | 면적 대비 가격이 비정상(특수 거래)이라 면적-가격 관계를 왜곡 |
| 정답 log1p | 평가 지표가 log RMSE, 가격 분포가 오른쪽으로 치우침 |
| 반복 5-fold × 3 | 1,458행이라 분할 한 번의 점수는 흔들림 |
| 스태킹 (OOF → 가중치 ≥ 0 선형회귀) | 기본 모델이 학습 때 보지 못한 예측으로 가중치를 정해야 과신하지 않음. 음수 가중치는 불안정 |

### v1: CatBoost(카테고리) + Ridge(수치형)
```
카테고리 44 ─────────────────────→ CatBoost ─┐
                                              ├─→ 메타 (0.19 / 0.84) → Kaggle 0.13585
수치형 51 → log1p → 표준화 → Ridge ──────────┘
```
- **기법:** CatBoost 는 카테고리를 그대로 처리. Ridge 는 치우친 피처 log1p, 표준화, 규제 강도 교차검증 선택.
- **이유:** 처음 정한 역할 분담. 수치형 모델은 교차검증으로 Ridge(0.1206)와 LightGBM(0.1249) 중 선택.
- **결과:** 교차검증 0.1184 인데 Kaggle 0.13585 로 차이 0.017.
- **원인:** test 의 **Id 2550** 이 거주 면적 5,095 / 총면적 10,190 sq ft 로 학습 최댓값(4,476 / 6,872)을 크게 넘는다. Ridge 가 직선을 연장해 **101만 달러**를 예측했다(학습 최고가 75.5만 달러). 교차검증에는 범위 밖 집이 없어서 이 약점이 보이지 않았다.

### v2: CatBoost(카테고리) + LightGBM(수치형)
```
카테고리 44 → CatBoost ─┐
                         ├─→ 메타 (0.22 / 0.80) → Kaggle 0.12967
수치형 51 → LightGBM ───┘
```
- **기법:** 수치형 모델을 트리로 교체. 잎 8, 학습률 0.01, 행·열 샘플링으로 보수적 설정.
- **이유:** 트리는 범위 밖 값도 학습 범위 끝 구간처럼 취급해 폭주하지 않는다 (Id 2550 → 62만 달러).
- **결과:** 교차검증은 0.0016 나빠졌지만 Kaggle 은 0.0062 좋아졌다. **교차검증 순위와 Kaggle 순위가 뒤집힐 수 있다.**

### v3: CatBoost(카테고리) + MLP(수치형)
```
카테고리 44 → CatBoost ───────────────────────────────────────────┐
                                                                    ├─→ 메타 (0.23 / 0.79) → Kaggle 0.13941
수치형 51 → log1p → 학습 범위로 자르기 → 표준화 → MLP(128→64) × seed 3 ┘
```
- **기법:** scikit-learn MLP (ReLU, L2 규제, 조기 종료, seed 3개 평균). 입력을 피처별로 학습 범위 안으로 자름.
- **이유:** 딥러닝 계열 비선형 모델 시험. ReLU 는 범위 밖에서 직선이 되므로 입력을 잘라 대응.
- **결과:** MLP 단독 교차검증 0.1356, Kaggle 0.13941.
- **원인:** 피처를 하나씩 잘라도 Id 2550 을 **103만 달러**로 예측. 여러 피처가 동시에 최댓값인 조합은 학습 데이터에 없어서 다시 직선으로 연장됐다. 데이터가 작아 재학습마다 예측이 흔들렸다 (fold 모델과 전체 재학습 모델의 test 예측 상관 0.988, 트리는 0.996~1.000).

### v4: 3개 모델 스태킹 + 보호 장치
```
카테고리 44 → CatBoost ─┐
수치형 51 → LightGBM ───┼─→ 메타 (0.19 / 0.43 / 0.41)
수치형 51 → MLP ────────┘      ├ A: MLP 예측을 정답 가격 범위로 자르기 → 0.12992
                               └ B: 학습 범위 밖 test 23채는 MLP 빼고 예측 → 0.12965
```
- **기법:** 모델 3개 스태킹. 보호 장치 A(예측값 자르기), B(범위 밖 집은 그 모델 제외 = CatBoost+LightGBM 메타로 예측).
- **이유:** LightGBM 과 MLP 가 서로 다르게 틀리는 부분을 상쇄. 보호 장치는 MLP 폭주 차단.
- **결과:** 교차검증 0.1173 (당시 최고). 보정 없이 Kaggle 0.13082, A 0.12992, B 0.12965.
- **교훈:** A 는 1채만 고쳐서 효과가 작았고, **B(범위 밖이면 그 모델 제외)가 효과적**. 다만 MLP 가 주는 추가 정보가 작아 v2 와 거의 같았다.

### 오차 분석 (v2 기준 교차검증 예측)
| 발견 | 수치 |
|---|---|
| 오차가 소수에 집중 | 상위 5%(72채)가 전체 제곱오차의 51%. 나머지 집의 RMSE 는 0.086 |
| 가장 싼 10% 를 과대 예측 | RMSE 0.224, 편향 +0.09, 오차 비중 35% |
| 상업 지역 `C (all)` | 10채뿐인데 RMSE 0.505, 실제의 약 1.4배로 예측 |
| 비정상 거래 `Abnorml` (압류·급매) | 101채, 오차 비중 22% |
| 동네 `IDOTRR`, 80년 넘은 집 | RMSE 0.27 / 0.17 |
| 두 모델이 같은 집에서 같이 틀림 | 모델 문제가 아니라 피처에 정보가 없거나 표본이 적은 경우 |
| **역할 분담의 한계** | LightGBM 은 거래 상황·용도 지역·동네를 못 보고, CatBoost 는 면적을 못 봄 (CatBoost 단독 0.170) |

### v5: 피처 공유
```
카테고리 44 + 수치형 51 ─────────────────────→ CatBoost ─┐
수치형 51 + 품질 등급 10(숫자) + 카테고리 4 ──→ LightGBM ─┴─→ 메타 (0.67 / 0.34) → Kaggle 0.12241
  (SaleCondition, MSZoning, Neighborhood, Functional)
```
- **기법:** 역할 분담 폐지. 품질 등급은 Ex=5…Po=1 순서형 숫자로. LightGBM 카테고리 분기 설정을 작은 데이터에 맞게 조정 (`min_data_per_group` 100 → 10).
- **이유:** 오차 분석에서 각 모델의 정보 부족이 가장 큰 한계로 나왔다.

| 조합 | CatBoost 단독 | LightGBM 단독 | 스태킹 | 메타 가중치 (Cat / LGB) | 두 모델 예측 상관 | Kaggle |
|---|---|---|---|---|---|---|
| 기존 역할 분담 | 0.1697 | 0.1233 | 0.1200 | 0.22 / 0.80 | 0.920 | 0.12967 |
| LightGBM 에 카테고리 추가 | 0.1697 | 0.1162 | 0.1154 | 0.13 / 0.88 | 0.930 | 0.12381 |
| CatBoost 에 수치형 추가 | 0.1138 | 0.1233 | 0.1141 | 0.96 / 0.05 | 0.991 | 0.12345 |
| **둘 다 (both)** | 0.1138 | 0.1162 | **0.1133** | 0.67 / 0.34 | 0.994 | **0.12241** |

- 가장 큰 개선은 CatBoost 에 수치형을 준 것 (0.170 → 0.114). **모델 구조보다 어떤 정보를 주느냐가 중요했다.**
- 두 모델 예측 상관이 0.92 → 0.99 로 올라 다양성은 줄었지만, 개별 모델이 좋아진 효과가 더 컸다.
- **Kaggle 순위가 교차검증 순위와 정확히 같았다.** 모두 트리라 외삽 문제가 없어서 교차검증을 믿을 수 있는 상태가 됐다.
- 오차가 컸던 그룹은 개선이 작았다 (상업 지역 0.505 → 0.464, 비정상 거래 0.212 → 0.200).

### v6: 하이퍼파라미터 튜닝 + seed 평균
```
v5 구조 그대로
CatBoost (튜닝) × seed 3 평균 ─┐
LightGBM (튜닝) × seed 3 평균 ─┴─→ 메타 (0.54 / 0.46) → Kaggle 0.12184
```
- **기법:** Optuna (TPE + MedianPruner). 첫 시도는 기존 설정. **튜닝 분할(random_state=7)과 최종 검증 분할(42)을 다르게** 둠. fold 마다 seed 3개 평균.
- **이유:** 설정 최적화와 학습마다의 흔들림 감소. 분할을 나눠 튜닝 분할에만 맞춘 설정을 걸러냄.

| 모델 | 시도 (완료/전체) | 튜닝 분할 기존 → 최적 | 최종 검증 기존 → 튜닝 | 최적 설정의 특징 |
|---|---|---|---|---|
| LightGBM | 89 / 112 (15분) | 0.1172 → 0.1149 | 0.1162 → 0.1146 | 잎 8→4, L2 규제 1→7.1, 샘플링 강화 (더 단순하고 강한 규제) |
| CatBoost | 9 / 18 (40분) | 0.1147 → 0.1141 | 0.1138 → 0.1139 | 기존과 거의 같음 → 효과 없음 |

| | 교차검증 | Kaggle |
|---|---|---|
| 튜닝 전 (v5) | 0.11327 | 0.12241 |
| 튜닝 후 단일 seed | 0.11310 | – |
| **튜닝 후 seed 3개 평균 (v6)** | **0.11301** | **0.12184** |
| v6 CatBoost 단독 | 0.11395 | 0.12288 |

- 튜닝·seed 평균 효과는 Kaggle 0.0006 으로 마무리 수준. 스태킹이 CatBoost 단독보다 0.001 좋아, 예측 상관 0.99 여도 섞는 이득은 남아 있었다.

### v7: v6 + Box-Cox Lasso 블렌딩 + 보호 장치
```
CatBoost (v6) ──────────────────────────────┐
LightGBM (v6) ──────────────────────────────┼─→ 메타 (0.16 / 0.22 / 0.63)
수치형 51 → Box-Cox ┐                       │        │
카테고리 44 → 원-핫 ┴→ RobustScaler → Lasso ┘        │
                       보호 장치: 학습 범위 밖 test 23채 → v6(트리) 예측 사용 → Kaggle 0.11870
```
- **기법**
  - **Box-Cox:** 치우친 피처마다 분포를 정규에 가장 가깝게 만드는 강도(λ)를 학습 데이터에서 찾아 변환. log 는 λ=0 인 특수한 경우.
  - **원-핫:** 카테고리 44개를 0/1 열로 펼쳐 선형 모델에 넣음 (3채 미만 범주는 버림).
  - **Lasso:** 필요 없는 피처의 가중치를 0 으로 만드는 L1 규제 선형회귀. 규제 강도는 내부 교차검증으로 선택.
  - **보호 장치:** v4-B 방식. 수치형 피처가 하나라도 학습 범위 밖인 test 집은 선형 모델을 뺀 예측(v6) 사용.
- **이유:** 트리끼리는 예측 상관 0.995 로 다양성이 없다. 선형 모델은 다른 방식(부드러운 추세)으로 예측하고, v1 에서 학습 범위 안의 강점을 확인했다. 폭주는 v4 에서 검증한 보호 장치로 막는다.

| 모델 / 조합 | 교차검증 | Kaggle |
|---|---|---|
| Lasso + log1p 단독 | 0.10942 | – |
| **Lasso + Box-Cox 단독** | **0.10921** (단독 모델 중 최고) | – |
| ElasticNet + Box-Cox 단독 | 0.10926 | – |
| v6 + Lasso(Box-Cox), 보호 장치 없음 | 0.1078 | 0.12101 |
| **v6 + Lasso(Box-Cox), 보호 장치** | **0.1078** | **0.11870** |

- 원-핫으로 카테고리 정보를 받자 선형 모델이 단독으로 가장 강해졌다 (v1 Ridge 는 수치형만 써서 0.1206).
- Box-Cox 효과는 log1p 대비 0.0002 로 미미했다. Lasso 와 ElasticNet 도 사실상 같았다.
- Lasso 단독은 Id 2550 을 **92만 달러**로 다시 폭주 예측했다. 보호 장치로 23채만 바꿨는데 Kaggle 이 0.0023 좋아졌다. **이 차이는 교차검증(둘 다 0.1078)으로는 보이지 않고 Kaggle 에서만 확인됐다.**

## 4. 오차 패턴과 오차 상관

> 프로젝트와 무관하게 일반화한 설명은 [루트 README: 오차 상관과 오차 분석](../README.md)에 있다. 이 장은 House Prices 에 적용한 구체적인 숫자와 의사결정 흐름이다.

전체 점수(RMSE) 하나만 보면 "얼마나" 틀리는지만 알 수 있다. 다음 수정 방향을 정하려면 **어디서, 어떻게, 어떤 모델들이 함께** 틀리는지를 봐야 했다.

### 4-1. 오차 상관: 앙상블의 이득을 결정한다

| 지표 | 계산 | 특징 |
|---|---|---|
| 예측 상관 | corr(모델 A 예측, 모델 B 예측) | 두 모델 모두 "비싼 집은 비싸게" 맞히므로 **늘 0.9 이상**. 차이가 잘 안 보임 |
| **오차 상관** | corr(A 예측 − 정답, B 예측 − 정답) | 정답을 빼고 **틀린 부분끼리만** 비교. 같이 틀리는지가 분명히 드러남 |

두 모델을 섞으면 서로 반대 방향의 오차가 상쇄된다. 오차 상관이 높으면 같은 실수를 하는 모델 둘을 섞는 셈이라 이득이 없다.

```
오차 상관 낮음:  A +10%,  B −8%  → 평균 +1%    (크게 상쇄)
오차 상관 높음:  A +10%,  B +9%  → 평균 +9.5%  (거의 그대로)
```

| 모델 짝 (교차검증 예측) | 예측 상관 | **오차 상관** | 개별 성능 | 해석 |
|---|---|---|---|---|
| v2: CatBoost(카테고리만) – LightGBM(수치만) | 0.920 | **0.515** | 0.170 / 0.123 | 다르게 틀리지만 **둘 다 약함** (정보를 나눠 가짐) |
| v6: CatBoost – LightGBM (피처 공유) | 0.995 | **0.948** | 0.114 / 0.114 | 강하지만 **거의 같이 틀림** (같은 정보, 같은 트리 방식) |
| v7: CatBoost – Lasso | 0.989 | **0.876** | 0.114 / 0.109 | **강하면서 어느 정도 다르게 틀림** (트리 vs 선형) |
| v7: LightGBM – Lasso | 0.988 | **0.865** | 0.114 / 0.109 | 〃 |

**좋은 앙상블 = 개별 성능이 높으면서 오차 상관이 낮은 모델들의 조합.**
- 두 조건은 맞바꾸는 관계였다. 정보를 나누면(v2) 다양하지만 약해지고, 정보를 공유하면(v5·v6) 강하지만 같아진다.
- 우선순위는 **개별 성능 → 다양성**. v2 → v5 에서 오차 상관이 0.515 → 0.948 로 나빠졌는데도 점수는 크게 좋아졌다.
- 다양성은 **보는 정보**보다 **예측 방식**(트리 vs 선형)을 다르게 해서 얻는 것이 좋았다. 같은 정보를 보면서도 다르게 틀리기 때문 (v7).
- 다양성을 주는 모델에 약점이 있으면 **막을 수 있어야** 쓸 수 있다. Lasso 는 범위 밖에서 폭주했지만 보호 장치가 있어서 블렌딩에 넣을 수 있었다.

### 4-2. 오차 패턴: 원인과 처방을 구분한다

| 관점 | 질문 | 이번 결과 (v2 기준) |
|---|---|---|
| 집중도 | 오차가 고르게 퍼졌나, 몇 채에 몰렸나? | 상위 5%(72채)가 전체 제곱오차의 51% |
| 그룹별 크기 | 어떤 종류의 집에서 많이 틀리나? | 상업 지역 0.505, 압류·급매 0.212, 가장 싼 10% 0.224 |
| 편향 (방향) | 한쪽으로 체계적으로 틀리나? | 가장 싼 10% 는 +0.09 과대 예측, 비싼 집은 과소 예측 |
| 모델별 비교 | 그 그룹에서 어느 모델이 더 틀리나? | 품질 10인 집: CatBoost 0.39 vs LightGBM 0.14 |
| 개별 사례 | 가장 크게 틀린 집은? | Id 31 (상업 지역, 1920년 건축): 실제 4만 → 예측 9.4만 달러 |

**패턴별 처방**

| 오차 패턴 | 의미 | 처방 | 이번 사례 |
|---|---|---|---|
| **한 모델만** 크게 틀림 | 그 모델의 문제 (정보 부족, 외삽, 설정) | 모델 교체·정보 추가·약점 차단 | v1 Ridge 외삽 → v2 교체, v4 MLP 폭주 → 보호 장치, CatBoost 면적 부족 → v5 |
| **모든 모델이 같이** 틀림 | 데이터의 문제 (피처에 정보 없음, 표본 부족) | 새 피처·그룹별 별도 처리. 모델을 바꾸거나 섞어도 안 됨 | 상업 지역(10채), 압류·급매 — v5 이후에도 거의 그대로 |
| 한 방향으로만 틀림 (편향) | 그 그룹을 체계적으로 잘못 이해 | 그 그룹을 구분하는 피처 | 싼 집 과대 예측 |
| 극소수에 몰림 | 대부분은 이미 잘 맞힘 | 그 소수만 공략하거나 한계로 인정 | 상위 5% 를 빼면 RMSE 0.086 |

"모든 모델이 같이 틀리는 집"은 곧 오차 상관이 높은 부분이다. 그래서 두 분석은 연결된다: **오차 상관이 높은 영역은 앙상블로 해결되지 않으므로, 오차 패턴으로 그 영역을 찾아 데이터 쪽에서 고친다.**

### 4-3. 버전별 의사결정 흐름

```
v1  CV 좋은데 Kaggle 나쁨
     │  [개별 사례] Id 2550 → Ridge 101만 달러. 한 모델만 크게 틀림 → 모델 문제
     ▼  처방: 모델 교체
v2  Ridge → LightGBM                           Kaggle 0.13585 → 0.12967 ✔
     ▼  (가설) 다른 비선형 모델은?
v3  LightGBM → MLP                             0.13941 ✘
     │  [개별 사례] Id 2550 다시 103만 달러 → 같은 외삽 문제
     ▼  처방: 버리지 말고 다양성만 활용
v4  CatBoost + LightGBM + MLP                  CV 0.1173 (최고) / Kaggle 0.13082 ✘
     │  [상관] LightGBM–MLP 0.986 이지만 섞으면 CV 개선 → 다르게 틀리는 부분 있음
     │  [개별 사례] MLP 가중치만큼 Id 2550 폭주가 섞임
     ▼  처방: 범위 밖 집만 MLP 제외
v4-B                                           0.12965 (v2 와 같음)
     ▼  "CatBoost + LightGBM 자체를 어떻게 올리나?" → 오차 분석
[오차 분석]
     │  큰 오차 그룹이 LightGBM 이 못 보는 피처(거래 상황·용도 지역·동네)로 구분됨
     │  CatBoost 는 면적을 몰라 고가·고품질에서 약함
     │  → 오차 상관 0.515 로 다양하지만 둘 다 반쪽 정보만 봄
     ▼  처방: 정보 공유 (다양성을 일부 포기하고 개별 성능을 올림)
v5  피처 공유                                   0.12241 ✔ (최대 개선)
     │  [상관] 오차 상관 0.948 → 거의 같이 틀림, 섞는 이득 바닥
     │  [오차 패턴] 상업 지역·급매는 그대로 → 모든 모델이 같이 틀리는 데이터 문제
     ▼  처방: 개별 모델 다듬기
v6  튜닝 + seed 평균                            0.12184 (미미)
     │  [상관] 트리끼리는 더 넣어도 다양성 없음
     │  필요: 강하면서 다른 방식으로 틀리는 모델 → 선형 (v1 에서 범위 안 강점 확인)
     │        약점(외삽)은 v4-B 보호 장치로 차단
     ▼
v7  + Box-Cox Lasso + 보호 장치                 0.11870 ✔
        트리–Lasso 오차 상관 0.87 (트리끼리 0.948 보다 다양) + Lasso 단독 0.1092 로 강함
```

| 단계 | 관찰 | 사용한 분석 | 판단 | 결과 |
|---|---|---|---|---|
| v1 → v2 | CV–Kaggle 차이 0.017 | 개별 사례 | 한 모델의 문제 → 교체 | ✔ −0.0062 |
| v2 → v3 | (가설) | – | 다른 비선형 모델 | ✘ 외삽 재발 |
| v3 → v4 | MLP 는 약하지만 성격이 다름 | 모델 간 상관 | 다양성 활용 | CV ✔ / Kaggle ✘ |
| v4 → v4-B | Id 2550 에 MLP 폭주가 섞임 | 개별 사례 | 약점만 차단 | ✔ 복구 |
| v4-B → v5 | 개선 방향 불명 | 오차 분석 | 두 모델 다 정보 부족 → 공유 | ✔ −0.0072 |
| v5 → v6 | 같이 틀림, 남은 오차는 데이터 문제 | 상관 + 오차 분석 | 섞어도 소용없음 → 다듬기 | 미미 −0.0006 |
| v6 → v7 | 트리끼리 다양성 없음 | 모델 간 상관 | 다른 방식의 강한 모델 + 보호 장치 | ✔ −0.0031 |

**돌아보면**
- 실험 중에는 **예측 상관**을 기준으로 봤고, 오차 상관은 정리하면서 처음 계산했다. 오차 상관을 처음부터 봤다면 v5 에서 "0.948 = 거의 같이 틀림"이 분명해서, 튜닝(v6)보다 다른 방식의 모델(v7)로 먼저 갔을 수 있다.
- v3(MLP)는 오차 분석 없이 가설로 시도했다. v1 에서 외삽 문제를 확인했으므로, 같은 연속 함수형 모델인 MLP 도 같은 문제를 겪을 것을 미리 예상할 수 있었다.

## 7. 회고

- **교차검증 점수만으로 모델을 고르면 안 된다.** v1(Ridge)과 v4(3개 모델)는 교차검증이 가장 좋았지만 Kaggle 에서는 졌다. 공통 원인은 test 에만 있는 학습 범위 밖의 집(Id 2550)이었다. ASHRAE 에서 배운 "검증이 실제 평가 조건과 맞아야 한다"는 교훈이 여기서도 반복됐다.
- **선형 모델과 신경망은 범위 밖에서 직선으로 연장된다.** 트리 모델은 학습 범위 끝 값에 머문다. 신경망은 피처를 하나씩 잘라도 "여러 피처가 동시에 극단"인 조합에서 다시 폭주했다.
- **약한 모델을 버리지 말고 약점만 막으면 된다.** 선형 모델은 범위 밖에서 폭주하지만 범위 안에서는 가장 강했다 (v7 Lasso 단독 0.1092). "범위 안은 블렌딩, 범위 밖은 트리"라는 보호 장치로 두 장점을 모두 살려 최고 점수(0.11870)를 냈다. v1 에서의 실패가 v7 의 설계로 이어졌다.
- **오차 상관과 오차 패턴이 수정 방향을 정해 줬다.** 한 모델만 틀리면 그 모델을 고치고, 모든 모델이 같이 틀리면 섞어도 소용없으니 정보를 늘리거나 다른 방식의 모델을 찾는다. 좋은 앙상블은 개별 성능이 높으면서 오차 상관이 낮은 조합이다 (4장).
- **오차 분석이 가장 큰 개선을 찾아 줬다.** 오차가 큰 그룹을 보니 "카테고리는 CatBoost, 수치는 다른 모델"이라는 역할 분담 때문에 각 모델이 반쪽 정보만 보고 있었다. 피처를 공유하자 교차검증이 0.1200 → 0.1133 으로 이번 실험 중 가장 크게 좋아졌다.
- **튜닝, seed 평균, Box-Cox 는 마무리 수준이었다.** 튜닝·seed 평균은 합쳐서 교차검증 0.0003, Box-Cox 는 log1p 대비 0.0002. 모델 설정보다 어떤 정보를 주느냐가 훨씬 중요했다. CatBoost 는 기존 설정이 이미 최적에 가까웠고, LightGBM 은 "더 단순하고 강하게 규제"하는 방향이 좋았다 (데이터 1,458행).
- **남은 오차는 피처로 설명하기 어려운 집들이다.** 압류·급매, 상업 지역처럼 표본이 적거나 거래 사정이 데이터에 없는 경우다. 이 이상 줄이려면 해당 그룹 전용 피처나 별도 처리가 필요하다.
- **교차검증을 믿을 수 있게 만드는 것이 먼저였다.** v5·v6 에서는 Kaggle 순위가 교차검증 순위와 정확히 일치했다. 범위 밖 외삽 문제를 없앤 뒤에야 교차검증 개선이 그대로 Kaggle 개선으로 이어졌다.
- **아쉬운 점:** 하루 제출 한도(10회)를 앞쪽 비교 실험에 다 써서, v5·v6 은 다음 날에야 점수를 확인했다. 보호 장치처럼 교차검증으로 판단할 수 없는 선택이 있어서 제출 기회를 아껴 둘 필요가 있다. 다음에는 교차검증으로 먼저 거르고 유망한 것만 제출한다. MLflow 서버를 켜지 않아 실험 기록이 파일(`result_*.json`)로만 남은 점도 아쉽다.
